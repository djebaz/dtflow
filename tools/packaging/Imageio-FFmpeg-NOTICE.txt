Imageio FFmpeg packaging experiment (Windows x64, DTFlow)
========================================================

This build is a size/compatibility experiment, NOT an accepted release input.

Video encoder:
  Distribution: imageio-ffmpeg 0.5.1, Windows x64 PyPI wheel
  Bundled executable: imageio_ffmpeg/binaries/ffmpeg-win64-v4.2.2.exe
  FFmpeg version: 4.2.2
  Wheel: https://pypi.org/project/imageio-ffmpeg/0.5.1/
  Asset:
  https://files.pythonhosted.org/packages/a9/1c/1b9c72bf839def47626436ea5ebaf643404f7850482c5fafd71a3deeaa94/imageio_ffmpeg-0.5.1-py3-none-win_amd64.whl
  SHA-256 (Windows x64 wheel):
    1521e79e253bedbdd36a547e0cbd94a025ba0b558e17f08fea687d805a0e4698

Independent stream inspector:
  Distribution: Gyan Doshi FFmpeg Essentials 8.1.2, Windows x64
  Bundled executable: bin/ffprobe.exe (not the imageio wheel)
  Asset:
  https://github.com/GyanD/codexffmpeg/releases/download/8.1.2/ffmpeg-8.1.2-essentials_build.zip
  SHA-256:
    db580001caa24ac104c8cb856cd113a87b0a443f7bdf47d8c12b1d740584a2ec
  Licensing: Gyan Essentials GPLv3; the upstream LICENSE and README
  are copied into DTFlow's licenses/FFmpeg directory.

The imageio-ffmpeg wheel is not installed as a runtime dependency. DTFlow
extracts only its FFmpeg executable, wheel license/metadata notices and
the independent Gyan ffprobe command during an explicit Windows build.
The original video encoding/probing subprocess arguments are unchanged.
Both wheel and Gyan ZIP are checksum-pinned; the staged executables and
notices are hashed again into the DTFlow build manifest.

IMPORTANT: FFmpeg 4.2.2 is an older upstream release with a separate
support/security lifecycle. This experiment is not an endorsement of it
for production; confirm actual libx264/AAC, raw RGB input, MP4 faststart,
FFprobe stream/fps/frame-count, playback and startup behavior on the
exact frozen Windows executable before considering it.
