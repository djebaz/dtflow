## Delivered additions and cross-cutting behavior

- **PR #150, pending merge:** recorded item settings/duration, cached thumbnails and Open in Images are implemented in source. Review corrections enforce live gallery authority, bounded revalidation, mapped availability, owned cancellation and composer evidence isolation. Focused tests and offline fixture definitions were extended; see the [current plan](plans/2026-10-21-queues-item-table-render-first.md) for evidence, not the older design-only PR description.

- **Queue workflow:** center composer/LoRA sets, quick Queue, Relaunch/Retry, editable captured-request inputs and ordered up-next dispatch; cloud Max at once 1–10 (default 4), elapsed/rough ETA and timing snapshots. Execution DB schema 4 backs up older state before migration; older builds reject it. Long inspector text and narrow composer controls wrap without losing values. [5.1.0 upgrade and limits](releases/v5.1.0.md).

- **Random planning and prompt variation (#145):** deterministic random dimensions, wildcard/template resolution and optional prompt mutations use the shared planner. Composer previews coalesce background work, reject stale results and refresh when retained image seeds or observed wildcard-file fingerprints change. [Planning delivery and evidence](plans/2026-10-04-phase-6-queue-planning.md#pr-145-review-and-validation). Native Windows interaction and responsiveness remain unverified.

- **Diagnostics and Logs (#105/#111 merged):** one rotating JSONL stream with typed producers and loss/closure accounting; shared Qt-free reader/query/export and migrated benchmark consumers. Native status-bar Logs has whole-session filtering and 500-row bidirectional pages, Follow, details/copy/export and active log-directory override; timing-chip rounding preserves raw precision. [PR #111](https://github.com/djebaz/dtflow/pull/111) implements the #108 split Component/Event sort targets, counted Refresh with visible incomplete status, an empty-state panel and non-consuming outside-click detail dismissal. It also adds live-session snapshot exports, progress/cancel and a conservative selection-byte refusal (not complete peak-memory enforcement). Historical text/CSV remains untouched. [Delivery audit](plans/2026-10-19-structured-log-viewer.md).
- **Windows benchmark tooling (#104/#105):** real UIA profile smoke and Grid `-ml/-mc` matrices, visible-position start/arrival verification, continuous down/back wheel journeys and warning/incomplete-trial exclusions. Single-run rankings are provisional; tooling does not establish an optimal production default or zero-stall browsing. [Benchmark plan](plans/2026-10-18-windows-gallery-benchmarks.md).
- **Windows/WSL1 (#73/#75/#76/#85):** guarded original-file leases/helper, verified read aliases, per-runtime export folders, saved-request reuse, model-readability checks and asynchronous desktop handoff. Browsing snapshots expose committed metadata during live-store refusal but never authorize export/edit/removal. [Snapshot architecture/evidence](architecture/gallery-snapshot.md), [WSL follow-ups](plans/2026-10-17-wsl-followups.md).
- **Developer support:** uv-managed agent setup, deterministic offline image fixtures, expanded named Qt preview states, Windows offscreen fonts/config fixes and parallel pytest. Preview definitions/screenshots remain layout evidence, not native interaction/DPI acceptance. [Development guide](guides/development.md), [testing guide](guides/testing.md).

## Evidence and operational limits

- The owner [confirms ONNX selection compatibility on older CPUs](https://github.com/djebaz/dtflow/pull/109#issuecomment-6265197891). The withdrawn unverified-CPU warning must not be repeated. Model-quality claims, standalone PoC cost measurements and acceptance of the exact release executable remain separate.
- Prior CI and owner source-run smoke observations belong to their recorded commits/configurations; follow the linked delivery plans for details. Do not reuse old test counts or skipped render jobs as evidence for the current release head. Ruff format/lint remain non-blocking in CI, so inspect actual step results even when a workflow is green. Baseline main `16a4170` passed lock/Ruff steps and 629 tests (3 skipped); release-head checks remain separate. See the release preparation plan for exact run identities.
- Do not run simultaneous Windows/WSL SQLite state writers. Unverified WSL2 Windows-drive mounts refuse original-touching operations; paths/outputs are not automatically migrated. Snapshots are browsing-only. A remote-successful generation may still fail local saving with absent/partial files; repeating generation may consume credits. [Cross-runtime guidance](guides/desktop.md#windows-history-viewed-in-wsl-1).
- Cache eviction is entry-count based, not a byte budget; queued thumbnail writes can republish after removal cleanup, and oversized legacy flat caches have separate cleanup limits. Remaining native stalls/startup latency are not fixed merely by changing benchmark configuration. [Current gallery caveats](plans/2026-10-17-images-hybrid-pagination.md).
- Exact 5.1.0 release-head checks and owner acceptance of the clean Windows executable remain separate gates under the [release guide](guides/releasing.md) and [preparation plan](plans/2026-10-21-release-5.1.0.md). No local tests/renders, builds, inference or provider actions are part of this preparation.
