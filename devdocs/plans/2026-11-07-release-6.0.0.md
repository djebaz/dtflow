# DTFlow 6.0.0 release preparation

Date: 2026-11-07. Owner-selected version: 6.0.0. A 5.5.6 candidate (PR #270, tag and draft) was built and smoke-tested but never published and is abandoned; 5.5.3 to 5.5.5 were never released. Build path: **Build Windows EXE and draft release** (`build-and-release.yml`).

## Scope and baseline

- Baseline: merged main `89cebe0866b71cceb3fdf62484f6bd4949c04448` (the 6.0.0 preparation commit). Published predecessor: [5.5.2](https://github.com/djebaz/dtflow/releases/tag/v5.5.2).
- Open PRs #253 and #254 are not merged and not part of this release.
- Only DTFlow's own version changes in `pyproject.toml` and `uv.lock` (lock revision unchanged). [Versioned notes](../releases/v6.0.0.md) consolidate the post-5.5.2 changes.

## Validation

- Owner instruction: no local tests; GitHub CI is the test evidence. Local checks: `uv lock --check`, Ruff lint/format. Exact-head CI results are recorded on the release PR.
- No model download, training, inference, upload or provider call is part of preparation.

## Delivery gates

1. Release PR with passing CI on its final head; squash merge.
2. Push annotated `v6.0.0` on the merged commit, dispatch `build-and-release.yml` from main with `release_tag=v6.0.0` (after checking no run is already active for that tag).
3. Verify draft asset identity, checksum and manifest; owner smoke-tests the exact executable.
4. Publish the existing draft only after owner acceptance and approval.

A tag, successful build or draft is not a shipped release.

The earlier 5.5.6 executable smoke does not carry over: the 6.0.0 build needs its own owner smoke.
