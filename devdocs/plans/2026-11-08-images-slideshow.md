# Images Detail slideshow

## Owner scope

Add a small PR for a fullscreen Detail slideshow. A checkable Slideshow button sits immediately after the buffered count; F6 enters/leaves while Images is active. Use 0.5–8 seconds in 0.1-second steps (default 3 seconds), loop through the current filtered gallery, replace the right-hand thumbnail carousel with the info card's prompt/LoRA content in a scrollable rail, and provide translucent controls that become opaque on hover/focus. The wheel changes rate only over controls; Left/Right navigate manually and restart the dwell. No provider/generation behavior, new store or automatic restart.

## Implementation

- `gallery_slideshow.py` is a page-parented QObject with a single-shot timer and canonical `gallery_slideshow.ui` controls. Entry selects Detail and optimized layout, suspends Live/Follow and enters native fullscreen; exit restores previous view/layout/window and Live/Follow mode without jumping to a newer image. F5, navigation away and shutdown stop playback. Escape also leaves after existing popup/inline-feedback precedence.
- Navigation reuses the gallery's bounded step/page query path and retains filters/sort. Both ends loop. No whole-library image enumeration or decoding on Qt. Loading/decoding waits rather than skipping; decoded results restart a full dwell. Read failures retain existing unavailable-image presentation; gallery-query failures stop playback.
- Slideshow image changes retain the current photo and its info card while decoding, then use an eased asymmetric fade lasting one third of the configured interval, targeting a fixed 60 updates/second to reduce CPU painting load. The surface painter retains at most one outgoing pixmap; a new transition replaces it, and completion/exit/error/empty state releases it. Ordinary browsing remains immediate. Failed reads still show an unavailable state rather than silently presenting the previous photo as the requested result. Smoothness is not established by static checks.
- At owner request, the outgoing photo now fades to zero in the first half of the transition while the incoming photo fades to one across its full duration. Both use smoothstep easing at the fixed 60 Hz target. This supersedes the incoming-only experiment; the asymmetric fade can visibly dip toward the canvas, and native brightness/smoothness acceptance remains pending. The old pixmap is released at completion.
- Owner reported strobing after the incoming-only change. Source inspection found that smooth scaling switched on only during fades, then off at completion; Detail now keeps it enabled across those boundaries. Incoming opacity uses a smoothstep ramp with zero endpoint slope. These are source-level corrections, not confirmation that the reported strobing is resolved; native owner smoke remains required.
- The translucent control group is inset at the image's top right. The Forward/Backward toggle displays the selected automatic direction (checked = Backward). Forward (default) follows the current filtered sort; Backward reverses it. Changing direction restarts the dwell without moving immediately; manual Left/Right remain previous/next regardless of automatic direction.
- Immersive playback hides the first (brand/view/tools) header row and reparents the existing second (range/buffered/batch) bar as a translucent top-of-image overlay, with no reserved layout height. The slideshow controls sit just below it at top-right. Both overlays disappear after 2.5 seconds without pointer/keyboard activity and reappear on activity; automatic photo changes do not reveal them. Existing popups and an active scrub keep them visible. Exit restores header visibility, bar ownership/order and normal styling.
- F6 is window-scoped and guarded by active Images/playback state, including when focus remains in sibling shell controls. A numbered photo-position slider uses filtered ordinals, previews the dragged number and commits a bounded seek on release (keyboard steps also seek). Latest busy seeks use existing coalesced page jumps; the ordinary decoded-result path resets the dwell. No whole-library enumeration is introduced.
- Wheel over the photo-position slider moves 10 photos per wheel event; wheel elsewhere over the control overlays adjusts rate. Wheel over the image retains zoom. Automatic playback direction does not reverse these manual wheel/arrow controls.
- During active playback, numpad + speeds up (0.1 seconds less dwell) and numpad − slows down (0.1 seconds more), bounded to 0.5–8 seconds. Held-key repeats are accepted. The same interval control handles persistence/countdown reset; ordinary keyboard plus/minus and modified shortcuts retain their existing behavior.
- Dragging, wheel bursts over the position slider and held Left/Right keys are positioning gestures. They pause auto-next, pending page jumps and new thumbnail/detail reads; only the target ordinal/label changes. Query/image results already in flight are retained in bounded one-result slots and their GUI application is deferred. Release (or 180 ms wheel quiet) commits the final target once. The scrubber remains pinned to that target until its decoded selection settles, so older/intermediate reads cannot snap it back. Admitted I/O is not claimed cancelled; native freeze/latency acceptance remains owner-owned.
- `GalleryHoverCard.set_dock` mounts the same already loaded info card in the canonical right rail, hiding the carousel during playback and restoring its prior visibility on exit. No extra metadata/provider reads. Shared token QSS gives a subdued grey presentation, with scrolling for long information. Controls are 35% opaque at rest and fully opaque during pointer/focus interaction; only their subtree intercepts wheel events.
- Rate and direction are saved through the existing debounced `viewer.json` preference writer, as optional `slideshow.seconds` (finite 0.5–8) and `slideshow.backward` (boolean) values. Missing/invalid values retain defaults, and unsupported/unreadable viewer files retain the existing preservation policy. No schema bump/new store: older applications may drop these optional convenience values when saving. Playback/fullscreen/position are never persisted as automatic resume authority. Existing view/Live preferences are restored on exit; durable saved images/selection authority and cache rules are unchanged.
