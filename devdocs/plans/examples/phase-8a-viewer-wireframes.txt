"12 new images" semantics and pagination/progressive loading remain to be defined.

REFERENCE AND STABLE LAYOUT
- Latest owner-approved reference: DTFlow Portrait Gallery Viewer_proc.png (Desktop mockup).
  This path identifies the discussed image; the image is not bundled in the repository.
- Grid, List and Detail are the only view modes. Masonry is removed from 8A scope.
- Detail contains the right-hand thumbnail filmstrip; Filmstrip is not a separate mode label.
- Give the image canvas most of the height, with a near-square preview at the reference size.
  Near-square describes the canvas, not a constraint to crop or reshape the source image.
- Keep metadata below and filmstrip right for all image proportions. Do not automatically
  move metadata to a side panel or rearrange the page when a portrait is selected.
- Keep one compact metadata band and a wrapping positive-prompt band beneath the preview.
- Additional details and Raw metadata JSON are buttons beside the prompt, not two permanent
  full-width accordion rows. Their contents stay closed until explicitly requested.
- Popup/drawer/dialog mechanics for those buttons remain unresolved; do not assume a modal.
- Long prompts and multiple/long LoRAs must remain accessible through wrapping or bounded
  scrolling, without uncontrolled preview shrinkage or automatic structural rearrangement.
- A user-adjustable preview/metadata divider was suggested, not explicitly approved.

METADATA PRIORITY / LAYOUT
- Dimensions belong on the image overlay, not in the metadata settings row.
- Position in filtered results also belongs on the image overlay.
- Model/checkpoint and LoRAs lead the first metadata row.
- Steps, guidance, sampler and generation date/time are secondary on that row.
- Aim for one compact row when it fits; wrap when names or LoRA lists are long.
  Any wrapping is a space-dependent fallback, not two mandatory metadata rows.
- Keep exact model/LoRA identifiers accessible; do not replace them with guessed labels.
- Show weights and recorded compatibility evidence; use Unknown without evidence.
- Positive prompt is visible by default. No green status dot is required for prompt text.
- Negative prompt is in Additional details, not the default visible prompt band.

ADDITIONAL DETAILS (button; contents closed by default)
  Negative prompt: full text
  Filename
  File size
  Actual resolved seed
  Provider
  Recorded generation duration
  Image path                         [Copy path] [Open folder]

RAW METADATA JSON (button; contents closed by default)
  Full saved metadata, with credentials/sensitive fields never exposed
  Request and attempt IDs
  DTFlow version and source commit
  Detailed recorded timing breakdowns
  Resolution/preflight evidence and other recorded technical provenance

NOT SHOWN
  Credentials, API keys, tokens
  Internal cache/index bookkeeping
  Invented settings/timings or inferred compatibility claims
  Future tags, ratings and notes (outside 8A)

VIEWING / NAVIGATION NOTES
- Cover fills the canvas proportionally and can crop the image; label this mode honestly.
- Fit shows the entire selected image without cropping, with unused canvas when necessary.
- Cover appears in the reference mockup; initial-mode and per-image mode persistence policy remain open.
- True 100% and current zoom percentage are distinct concepts; pan when zoomed.
- Previous/next and position counter follow current filtered/sorted results.
- The strip can scroll without changing the main image accidentally.
- An external-viewer action is required; its placement remains to be decided.
- A separate Inspector button on every browsing view is not required: open Detail
  from Grid/List, then use its visible metadata and detail buttons.
