# DTFlow 6.4.1 release preparation

Prepared 2026-11-16 from merged main `81d68eb7` through PR #498, after published `v6.4.0` (`bcf7adb6`). Release PR: [#499](https://github.com/djebaz/dtflow/pull/499). [Public notes](../releases/v6.4.1.md) remain concise and user-facing.

## Scope

- #485: DT+ timing records, opt-in `-time` detail and removal of repeated Echo calls.
- #490: performance measurements require both `-x` and `-perf`.
- #491: taller selected-LoRA list, per-row weight spin boxes and shared wheel stepping.
- #493: DT+ queue concurrency comes from Connection at each start; old queue/recipe limits are ignored.
- #495: slideshow New direction prioritizes new arrivals under Newest first sorting.
- #496: Civitai acceptance/documentation closeout, including token permissions and downloaded-source retention.
- #498: once-per-startup, off-thread stale download staging and orphan-source cleanup.
- Refresh the generated diagnostic-component catalogue if declarations have changed, before the canonical builder can mark the release dirty. Preserve the kmeans1d package-data collection and verification added for 6.4.0.

## Compatibility

- Execution schema remains 9; LoRA asset registry remains 6. Back up complete state and outputs; retain incompatible-schema refusals and no uncertain replay.
- Separate queue concurrency settings/CLI usage no longer govern dispatch. Connection's DT+ default is read for each start; already running items are not changed.
- No runtime dependency upgrades are part of this release preparation.
