# Retained-LoRA table responsiveness (#565)

## Cause and scope

[Issue #565](https://github.com/djebaz/dtflow/issues/565) reports Windows GUI gaps of 2098, 1778 and 584 ms with 96 retained files and three 1.1–1.2 s stall samples in `_render_lora_table` → `_fill_lora_table` → `_lora_row_actions`. These are owner-supplied historical measurements, not a new local profile or a measurement of this fix.

Source inspection identifies repeated work: entering Connection requests retained entries, family/format inspection, metadata/receipt reads and registry-only rows. The retained and family callbacks previously rebuilt unconditionally. The initial retained read also discarded family/format observations, forcing a second presentation change at scan completion. Independently, `GenerationPage.sync_backend` → `LoraPanel.sync_backend` → `set_enabled` requests a managed-table render even when its presentation has not changed. Every rebuild loaded `managed_lora_actions.ui`, connected two actions, polished widgets and recalculated geometry for every retained row. With 96 retained rows, that means 96 form loads per rebuild, including unchanged rows; this work matches the issue's sampled stack, but its individual timing has not been measured separately.

The original change is presentation-only. The owner expanded #565 on 2026-11-23 to include asynchronous catalogue setup, startup auto-connect and bounded changed-table reconciliation, then explicitly resumed implementation on the same PR #581. Generation, queues, provider protocols, credential precedence, upload consent and persistent schemas remain unchanged. In particular, the separately reported 4.3–7.1 s worker-side `families_ms` is not addressed or claimed fixed.

## Implementation

- Retain previous family/format/q8p observations for unchanged content identities while a new worker inspection is pending; its delivered result still replaces those observations, including unreadable/missing-file outcomes.
- Compare a copied presentation snapshot, including entries, metadata, no-copy records, formats, q8p availability, selected-key confirmations, backend and current busy state. An identical render request leaves the table and selection untouched.
- Reuse each existing row's canonical Designer action host. Update its current identity and metadata before enabling its controls; click handlers resolve those current values rather than an old row's captured identity. Existing eligibility, status text, tooltips and service calls remain authoritative.
- Mount at most one missing action form per timer turn, yielding between retained rows instead of synchronously loading the whole library. A replacement projection cancels the old pending list; each mount checks the row's current content identity and no-copy status. Busy state is read again at mount time. The timer belongs to the table/window and is stopped by the existing shutdown guard; callbacks also refuse work after runner shutdown starts.
- Suspend missing-host mounting during retained or registry-only removal and resume it on either completion, including failure/no-op outcomes. Source review caught a race where mounting under a temporarily disabled parent could otherwise leave child actions explicitly disabled after an unchanged failed removal.
- Keep the existing GUI-gap, stall-sample and retained-read diagnostics unchanged. No competing diagnostic writer or new sink is introduced.

## Owner-requested follow-up: AC-6 through AC-8

- Catalogue construction starts with an empty, I/O-free `Catalogue(deferred=True)`. `services/catalogue_setup.py` reads a fresh in-memory catalogue snapshot and computes family/checkpoint choices on a worker. Snapshot consumers do not stat/reread user metadata from GUI callbacks; metadata changes explicitly request another snapshot. Cold profile/community classification reads are warmed by the worker, and dependent presentation waits for catalogue readiness without pruning saved LoRAs.
- Only one catalogue read is admitted at a time, with one replaceable latest request. Request identity and backend/endpoint/inventory revision reject superseded results, including selected-key changes. Qt models are created and populated only on the GUI thread, at most 16 entries per timer turn, then swapped into the selectors with signals blocked. Existing choices remain visible during preparation; final selection follows the existing restoration/filtering rules. Swapping manually updates the sampler, video, meter, LoRA candidates and checkpoint steppers; obsolete detached models are discarded. The timer is page-owned and covered by the existing window shutdown guard.
- Startup auto-connect already submits `_check` to the shared `AsyncRunner`; credentials are read off Qt, and the shared connection service owns asynchronous provider access, timeout and cleanup. It remains independent of catalogue readiness and performs no generation/upload. No second event loop, provider runner or polling loop is added. The follow-up records the restored selection revision, skips the queued automatic check if an earlier explicit backend/endpoint/key edit superseded restoration, and refuses shutdown-time result presentation. An early manual Check still consumes the one automatic check. Existing per-check tokens, selection revision and environment-context guards remain authoritative.
- Changed LoRA contents, status cells and reused/new row controls now reconcile together one row per timer turn; excess rows are removed one per turn too. A superseding projection replaces the iterator, rather than completing the old work. Selection restores by exact content identity; a newer selection of an already reconciled row wins. Old/unreconciled rows cannot supply a selection identity. Metadata/removal actions wait for reconciliation; row-action handlers recheck pending work and current busy state instead of trusting a still-visible old enabled button. Existing eligibility/approval services remain unchanged. No whole-table paint suppression spans multiple turns.
- Presentation snapshot comparison excludes descriptive source metadata that the table does not display, avoiding a full copy of that unrelated per-file payload on every render request. Canonical metadata remains available to the existing explicit metadata overlay.

These are structural source properties, not a measured GUI latency guarantee. Row actions temporarily refuse activation while a newer table projection is pending; selected-row Edit/Remove controls stay disabled until reconciliation completes. Owner smoke should include rapid filter/model/key/backend changes while a catalogue read or table update is pending, selection during partial updates, superseded restoration, metadata reload, failed removal, and closing during both worker and GUI-batch work. The follow-up's changes to asynchronous delivery may require subsequent CI-maintained coverage; no tests or fixtures were changed by the development agent.
