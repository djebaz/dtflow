# Plan: Structured JSONL diagnostics and native Logs workspace

## Goal and scope

Implement issue #96 on top of merged PR #104 (`2945157`): purpose-designed structured diagnostic evidence for agents and benchmark tooling, presented to humans as a clean, newest-first native Qt table. One standard-library logging pipeline owns application, backend and gallery diagnostics. Logs remain diagnostic evidence, never generation state or proof of success.

- In: JSONL schema/writer, typed DTFlow emitters, existing gallery aggregation semantics, new-session readers, CSV export, benchmark reader migration, and an in-window Logs workspace.
- Out: legacy text/CSV adapters or conversion, gallery optimization, provider changes, inference, model downloads, new runtime dependencies, release/version bump, packaged build, and changes to durable job/output schemas.
- Existing `.log`/gallery CSV evidence remains untouched. New sessions write only `dtflow-<session>.jsonl` and its rotated siblings; benchmark result CSV/JSON artifacts remain reports, not parallel logging sinks.
- Permanent companion references: [structured diagnostics ownership and evidence boundaries](../architecture/structured-diagnostics.md) and [Qt model/view performance patterns and implementation references](../guides/qt-model-view-patterns.md). These are explanatory guides; **this plan and its G1–G6 acceptance guards remain authoritative**. The design targets are not yet runtime behavior.

All test reconciliation is deferred until the implementation phases are finished; list affected contracts without editing them. Owner/CI execute acceptance after that deferred work. Existing CI can fail old-format expectations during implementation; keep that explicit and never disable checks to conceal it.

## Event contract (schema version 1)

Each UTF-8, BOM-free physical line is one JSON object with a terminating LF. Escape multiline messages/tracebacks inside JSON strings; never pretty-print records across physical lines. Disallow non-finite numbers and arbitrary object reprs in structured fields.

- Required envelope: `schema_version` (integer 1), `session_id`, `seq` (unique increasing persisted record order), `timestamp` (source UTC ISO-8601 with milliseconds), `monotonic_ns` (source monotonic clock), `level`, `component`, `event` (stable dotted identifier), `kind` (`event`, `measurement` or `aggregate`), `message` (concise human summary), and `data` (typed JSON object).
- Optional `context`: backend, job/attempt/operation IDs and benchmark run/trial/action IDs only when actually available. No placeholders for absent context and no invented causal links.
- Optional `error`: sanitized exception type, message and complete traceback without locals for an accepted record within the shared size limit. Oversized original diagnostics are explicitly rejected and represented by loss metadata, never silently shortened or described as complete (G2/G3 below). Preserve exception structure before queue preparation can flatten it into the message.
- Optional `aggregation`: sample count and source window bounds, with explicit per-metric count/mean/p95/max/total where measured. Keep units explicit in field names (`*_ms`, `*_bytes`); do not fabricate percentiles or average window percentiles into a global p95.
- `session.started` records full available build identity, dirty/unknown state, runtime/platform and diagnostic mode. All records identify the session; the viewer can join session metadata without repeating the full environment in every row.
- Introduce a small typed logging helper around standard logging. Migrate DTFlow-owned call sites to explicit event names and typed arguments, including gallery timings, rather than parsing formatted messages in the live writer. Plain standard-library messages have a clearly generic diagnostic fallback, not guessed fields.
- Sanitize text recursively before persistence and again at viewer/export boundaries. Preserve the existing secret-environment and credential/payload redaction protections; never capture full prompts, raw image data, prepared cloud references, private paths or exception locals.

## Accepted owner-review guards

These requirements incorporate the owner's [five plan-contract findings](https://github.com/djebaz/dtflow/pull/105#pullrequestreview-5566293375), [centralization requirement](https://github.com/djebaz/dtflow/pull/105#pullrequestreview-5566302282), and [clarification](https://github.com/djebaz/dtflow/pull/105#issuecomment-6258326091). They are required design/implementation guards, not claims that code or verification already exists. Concrete capacity bounds below are proposed initial safety defaults for owner plan review, not accepted performance measurements. All implementation phases remain pending.

### G1 — Strengthen existing ownership; do not build a competing subsystem (Phases 1–3)

- Keep `logging_setup.py` / `configure_logging` as the single composition, configuration and lifecycle authority. Preserve its working standard-library queue/listener, privacy, rotation, retention and nonblocking-producer behavior; replace only obsolete representations and fragmented interpretation. Focused internal modules are permitted, but neither a wholesale rewrite nor a mandatory giant facade is required.
- Keep two narrow producer interfaces: ordinary `logging.getLogger(__name__)` for generic/third-party messages and a typed emission helper for DTFlow-owned semantic events/measurements. Typed producers pass structured values at the existing measurement site; they never hand-build JSON or encode machine fields in formatted message strings. Do not globally capture unrelated third-party loggers or change their effective levels/propagation; records reaching the configured subsystem use its generic-message path.
- One internal schema/privacy implementation owns field definitions, validation, recursive redaction, error extraction and serialization. Central capture records source clocks/context before queueing; only the listener owns persisted `seq`, normalization, aggregation, file writing and rotation. UI/services/backends import producer APIs, never writer/aggregation internals. Neither UI nor benchmark modules may add diagnostic `json.loads`, regex/event remapping, independent redaction or alternative schema definitions.
- One Qt-free reader/validator is shared by the viewer, exports and #104 tools. Presentation and scoring remain owned by their callers. Existing benchmark result/trial artifact writers remain allowed explicit report producers; they must not become parallel persistent diagnostic streams. Exports are explicit derived operations, never automatic sinks.
- Phase 1 documents these allowed imports and bypass restrictions in AGENTS. Phase 2 inventories/removes the current string-parsing aggregation/CSV fanout and benchmark log parsers. Deferred boundary review/CI must reject newly scattered persistent handlers, diagnostic writers, session/sequence counters, retention/location policies, schemas or parsers outside the owned subsystem.

### G2 — Bounded admission and explicit evidence completeness (Phase 1; consumed by Phase 2)

- Replace the unbounded queue with nonblocking admission bounded by both 1,024 pending data records and an 8 MiB conservative payload budget. These are initial safety bounds, not measured throughput claims. Shared capture snapshots only permitted JSON-native values and source metadata, with bounded traversal (depth 16 / 4,096 nodes); it must not enqueue arbitrary mutable object graphs, exception locals or objects retained only for a future repr. Admission accounts for retained string/byte sizes conservatively; final JSON serialization remains on the listener, not at measurement call sites. Oversized/unsupported capture is rejected explicitly rather than bypassing the budget. Keep generic logging supported through the same central bounded preparation path.
- If admission would exceed either bound, drop the incoming record without blocking the caller. Atomically count rejected/dropped records by reason and severity plus whether diagnostic measurements were affected. Do not recursively log a logging failure. The listener emits a small `diagnostics.loss` control record when able; loss counters and startup/close control requests must not depend on finding another data-queue slot. Shutdown uses an out-of-band control request, not a sentinel that can fail because the queue is full.
- Source observations/admission and persisted output are separate counts because intentional aggregation is not loss. `session.started` declares schema, instrumentation, admission/size limits and aggregation policy. After producers detach, admitted records drain and aggregates flush, the listener attempts a final `session.closed` seal with final `seq`, observed/admitted/rejected/dropped counts, aggregate source-sample counts and writer/serialization failure counts. No success seal may be emitted before all pending work is accounted for; a shutdown deadline or writer failure leaves the session unsealed. A one-time sanitized user warning is supplementary, never proof that evidence is complete.
- Serialization failure replaces that record with a small safe rejection/loss record identifying only the original event identity and reason, increments the counters, and invalidates clean evidence. Disk-full/partial-write or other persistent sink failure disables that sink for the run, reports once, and cannot yield a successful seal. Do not retry generation, block Qt waiting for disk, or write fallback diagnostic files. Missing files/seal, nonzero loss/rejection/write counters, incompatible records, conflicting duplicates or required sequence gaps make benchmark evidence incomplete; they must never become zero stalls or a ranked clean trial. The viewer may still browse readable records with an explicit incomplete banner. Active sessions are pending, not certified complete; live readiness can observe valid records without certifying final benchmark completeness.

### G3 — One size/traceback policy across writer, reader and export (Phases 1–3)

- The shared maximum physical record is 1 MiB of UTF-8 JSON including LF; final encoded length is checked after sanitization. The conservative admission bound may reject earlier; record its distinct reason. Keep the existing 1,000,000-byte rollover target: a single intact accepted line may exceed that target, but never the shared 1 MiB maximum. Never split a record across lines/files or truncate JSON, messages or tracebacks to force acceptance.
- If the sanitized event/traceback exceeds the limit, persist only a bounded `diagnostics.record_rejected` marker when writable, with the original event identity, reason, measured/estimated size, limit and `original_content_available=false`. Do not persist a misleading traceback prefix or claim the original evidence was retained. Update G2 counters/completeness. This explicitly narrows the earlier unconditional complete-traceback wording: full details are guaranteed only for accepted supported-size records.
- Readers enforce the same bound with a limited readline, not unbounded `readline()` followed by a size check; consume/discard an offending line in bounded chunks and surface corruption/incompleteness. Viewer details and readable/JSONL/CSV exports show the rejection/unavailability metadata and do not invent the missing original. Unknown oversized on-disk records are reported, not silently skipped or presented as valid evidence. Copy/export of accepted records retains their full sanitized traceback and escaped newlines.

### G4 — Rotation, deduplication and bounded whole-session queries (Phase 2)

- Canonical segment names are `dtflow-<session>.jsonl` and `.jsonl.1` through `.jsonl.3`. Open verified regular, nonredirected files; capture handle identity and size for a read snapshot. Physical handles/offsets drive I/O, but `(session_id, seq)` drives logical identity. Never infer order from filenames, mtimes, byte offsets or listener delivery time in another session.
- Decode complete newline-terminated records only. Hold an incomplete active-tail record until more bytes arrive; a closed/pruned/replaced tail that never completes is incomplete evidence. Re-enumerate after rename/rollover, follow the current segment, deduplicate identical logical records and reject conflicting copies. Handle an old pathname becoming a different file, pruning behind the cursor, retained-prefix loss, midstream sequence gaps and a missing startup/seal explicitly. Restart from a stable snapshot on a rotation race; do not merge incompatible snapshots and call them complete. Bound retries to three, then return an interrupted/retryable result rather than spin forever.
- Every UI session/filter/sort/read request carries a generation token and snapshot boundary. Cancel worker scans and discard all stale results after filter/session/navigation/shutdown changes. Follow cannot duplicate records or rewrite selected details. Exports pin their selected snapshot boundary; warn or abort if required retained segments disappear. Benchmark readers require the declared complete schema/instrumentation contract after process exit; a live file's temporary EOF is not a completeness signal.
- Full-session sorting/filtering must not build an all-record list or a growing offset-sized heap. Scan the retained snapshot on a worker, count matches, and select each 500-row page with bounded top-k/keyset paging; include `(session_id, seq)` as the deterministic tie-breaker. Search/filter/sort apply before page selection. Use a fixed 500-candidate heap, bounded per-record buffers and cancellation checks at least every 128 records, with at most 10,000 display rows resident. Whole-session exports stream the same shared query pages. Explain that counts cover the retained snapshot, and visibly mark pruned-prefix loss; a resident-page limit must never masquerade as a full-session match limit.
- Row count alone is not a memory bound: keep lightweight row projections and validated file/seq locators, not 10,000 full 1 MiB records. Cap the resident model/projection storage at 32 MiB and worker scan/page/cursor storage at 16 MiB; evict display pages before either resident limit is exceeded. Candidate heaps retain bounded displayed-column sort keys/locators, not full messages/tracebacks. Document that table sorting uses those displayed projections; full accepted content remains searchable in the streaming scan and readable on demand. Fetch selected details/copy/export content through the same worker reader and explicitly report when rotation removes it; do not retain hidden unlimited payload caches. Exceeding a worker query budget returns a clear bounded-result failure, never a falsely complete match count or partial export labeled complete.

### G5 — #104 contract inventory and parity gate (Phase 1 inventory; Phase 2 migration)

Freeze the following baseline facts before migrating its producers/readers. New semantic event names map centrally to these meanings; consumer modules may not recreate their own mappings. `seq` is only persisted identity/order. Stall-to-wheel attribution always uses the source UTC timestamp, never the listener/flush timestamp or persisted order. Aggregates keep their source-window bounds rather than acquiring a synthetic source time when flushed.

| Existing contract | Required migration guard |
| --- | --- |
| `query_done`: `returned` and `error=none`; rotated-log identity used by readiness | Typed success/error and positive returned count retain the same success condition. Freshness uses session/seq, not the largest historical row count. A new valid query must not be inferred from an aggregate or malformed record. |
| `scroll_intent`: `direction=forward/backward`, `source=wheel`, mode/offset/mounted observations | Preserve direction/source and source timing. Do not count non-wheel or aggregate-only observations as an individual wheel receipt; ensure the typed event needed by readiness remains individually observable rather than batching it away. Do not confuse receipt with reaching a target. |
| Pager/UIA position evidence and `grid-seek-down`/`grid-seek-up` action timestamps, duration and `target_reached` | First visible saved-image index remains authoritative, not catalogue totals, buffered counts or the end of a visible range. Keep start/end timestamps and complete down/back legs for every cycle; a log migration must not replace UIA position verification with event guesses. |
| Source GUI heartbeat: samples at >=50 ms; individual `gui_gap` emitted at >=100 ms with mode, mounted, query/preparation busy | Preserve source measurement/cadence and individual outliers. Grid scoring requires >=100 ms, mode Grid and mounted >0, inside actual down/up input intervals; exclude startup. Never count an aggregate and its individual outlier twice. |
| Listener batching of `thumbnail_worker`, `thumbnail_end_to_end`, `scroll_intent`, `prepare_slice`, `gui_gap` | Preserve 64-sample / 10-source-second triggered batches and close flush, dimension grouping (direction/source/mode/success), per-metric sample count, mean, nearest-rank p95, maximum and total. An individual record intentionally retained for readiness/outliers is not additional aggregate sample population. |
| Source `_PerfBatchStats`: samples/items, wall total/average/max, CPU total, failures; approximately two-second heartbeat-driven flush | Preserve populations, measurement clock and failure counts. Add explicit source-window metadata without presenting a pre-aggregate as raw samples or inventing a p95 from its mean/max. |
| Derived gallery CSV: utc/phase/metric/samples/mean/p95/max/total/details; `_ms` fields and `_summary` statistics | Replace the automatic sink with typed fields and explicit export; do not parse a new message string to regenerate old columns. Preserve the measured units and distinguish raw values from summary statistics. |
| #104 `summarize_csv` report: query/adjacent counts, GUI gap max, recorded medians, phase counts | Preserve baseline calculations in the migration and explicitly label their interpretation: source currently collects CSV `max`, so recorded medians are medians of those maxima, despite its docstring mentioning means. `phase_counts` currently sums samples per metric row. Record these legacy report conventions in report metadata; do not silently change them into global sample medians or unique-event counts. A scientific correction needs a separately approved change. |
| Clean-trial ranking | Require successful status, no warnings, verified first-visible journey, all expected legs/targets, compatible instrumentation and G2/G4 completeness. Keep ranking by average >=100 ms stall count per trial, worst counted gap, median round-trip duration, then the existing deterministic configuration ties. Keep single-run leaders provisional and >=3 clean trials/configuration for repeatability. Missing/damaged evidence has explicit unavailable/incomplete fields, not numeric zero; only complete observed no-stall intervals may report zero. |

The intentional timestamp-precision change is explicit: use source millisecond timestamps against the recorded timezone-aware action intervals, not the text logger's whole-second boundary widening. Version this attribution policy in report metadata and disclose that new and old boundary counts are not directly identical. Do not mix policies within a comparison or use this exception to change thresholds, populations, targets or ranking. Keep source monotonic time for elapsed measurements; only compare monotonic clocks across processes when the common clock domain has been explicitly established, never merely because units match.
