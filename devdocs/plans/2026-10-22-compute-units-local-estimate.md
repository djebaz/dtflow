# Local Compute Units estimate in Generate

**Status:** source implementation in PR #153; unmerged and pending owner acceptance. **Scope:** a read-only local estimate; no billing, entitlement, upload, generation or catalogue changes.

## Source of truth and limitations

- The upstream Draw Things community sources are `Libraries/ModelZoo/Sources/ComputeUnits.swift` (blob `b4d64fd012d3d603c04a623fa18943c9fdd15307`), the architecture-specific `Libraries/SwiftDiffusion/Sources/Models/InstructionCount/*.swift` functions and `Sampler.swift` for CFG channels.
- Reproducible source revision for all those files: [`82bd56c81a313060dceb34092bcf9d671c39a739`](https://github.com/drawthingsai/draw-things-community/tree/82bd56c81a313060dceb34092bcf9d671c39a739); its ComputeUnits blob matches the one above. Continuation review compared supported-family arithmetic against those sources by inspection, not by executing a parity check.
- The estimator counts Dense / attention / convolution operations, uses a calibration factor `5.14816e-12` and a model usage policy multiplier. **Do not** substitute `default_scale`, filename quantization, `hires_fix_scale` or an arbitrary per-model coefficient.
- Resolve exact technical metadata from the existing `community_model_specs.json`. When absent, use an existing classification to select a supported base architecture and profile/default inputs for a base estimate, never another file's technical description. `Models_prime.json`, `Models_niche.json` and `model_profiles.json` remain independent. The profile describes DTFlow's actual wire defaults, not cloud availability.
- DTFlow emits a selected subset of Draw Things generation options. Display a **local estimate, not verified server cost**: server policy, versions, final effective configuration and quota may differ.

## Implementation

1. Add an isolated, dependency-free `core/compute_units.py` and `resources/compute_unit_architectures.json` with upstream instruction primitives and a **bounded, named set** of currently relevant T2I architectures: FLUX.1, FLUX.2 Dev/Klein, Z-Image, Qwen-Image 2.1, Qwen-Image, Krea 2 and Ideogram 4. All constants derive from the pinned upstream source, without any new merged catalogue.
2. Accept current T2I settings (model exact filename, classified base family, size, steps, guidance, known guidance-embed/profile settings). Calculate synchronously with no provider connection, storage write or service worker. Unsupported modifiers omit modifier costs and show the base count. Missing exact metadata uses the classified base family, including `flux_1` → `flux1` and `flux_2` → `flux2`, with profile/default inputs. These broad classifications do not identify a specific variant. Return `None` for unknown/unsupported architectures, missing profile evidence when needed, image editing, but not for selected unknown LoRAs (base estimate instead). No fuzzy filename match, substituted technical description or fabricated zero.
3. Show the estimate as a compact **meter** on the Checkpoint label row in Generate › Backend: `Checkpoint` label, the accepted info button (icon/label styling untouched), then the meter filling the rest of the row (`computeUnitsMeter`, a `QProgressBar`; the former full-width label below the selector is removed). Refresh on model, size, steps, guidance and relevant request-mode changes. Local Draw Things and direct DT+ Cloud show the meter regardless of the Local Include DT+ Cloud catalogue checkbox; fake hides it. Local display is a DT+ equivalent estimate and does not imply that local execution is billed.
   - **Scale:** 0 to 40 000 CU, left to right. Below 40 000 the fill is blue (muted tint of the accent). At 40 000 and above the meter stays full and turns red (muted error tint, number in the danger text colour).
   - **Text:** the number only, left-aligned inside the meter, 8pt. No "Estimated…" label, no "CU", no `~`. Thousands are separated by a narrow no-break space (U+202F), e.g. `100 000`.
   - **Unsupported states:** an empty meter reading `unavailable`, in placeholder colour. Never a fabricated 0. The reason is exposed through `accessibleDescription` only.
   - **Geometry:** 16px tall, `radiusSm` corners, input surface with a 1px border; the label row stays a fixed height so the meter never shifts the layout. Vertical rhythm of the Backend panel: 8px between field rows, 12px above the Checkpoint group with 4px between its label row and selector, the two buttons grouped at 6px, the inventory caption 6px under them.
4. **No hover overlay** (owner decision, replaces the earlier tooltip). The CU section in Checkpoint details shows only the CU value and supported models. Formula, derivation and limitations remain in developer documentation, not the overlay. Never present the result as remaining credits, authorization, exact billing, or a guarantee of request acceptance.
5. Keep the estimate out of the wire request, durable state, billing paths, queue scheduling, preflight and cloud authentication. Preserve the existing Generate behavior.

## Approved extension: architecture registry and LoRA fallback (2026-10-22)

- Place **versioned, pinned Draw Things architecture parameters** in a new bundled JSON registry. Entries identify supported upstream model versions, named instruction-count strategy, structural constants, latent/text defaults and policy multiplier; Python owns reusable dense/attention/convolution primitives and architecture-specific composition. An entry never substitutes for a missing model-specific formula. The registry is not a new model catalogue and is never transmitted to DT+.
- Exact-file community descriptions select a model version; a trusted existing family classification may select a **base architecture estimate** without copying a sibling's technical metadata. Quantization must not be used as a cost multiplier. Missing or invalid registry entries must fail safely, not fabricate zero or silently borrow another architecture.

Mark its provenance as a base estimate in the existing accessible description, not as confirmed billing. Do not assume unknown adapters have zero runtime overhead.

Port one named strategy at a time; never mark a version supported on the strength of JSON constants alone. Video families require request-specific frame/audio/reference context and an actual DTFlow generation path, so keep them documented but unavailable in the current single-image Generate meter.
- Audit source and changed diff only. Per owner instruction, **do not add or run tests**, including render fixtures or manual CI. Do not submit provider requests or perform billable operations. Document missing mathematical ports honestly; parity with upstream or server CU is not established merely by static inspection.
