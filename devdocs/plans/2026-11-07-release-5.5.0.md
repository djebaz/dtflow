## Delivery gates

1. Create the release PR early, verify its number and final-head CI, then squash merge only after the required checks pass.
2. Fast-forward clean local main to the exact release merge commit; verify metadata, notes and no existing conflicting tag/release.
3. Create/push annotated `v5.5.0` on that commit and verify the remote tag before dispatch.
4. Dispatch `build-and-release.yml` from `main`, with `release_tag=v5.5.0` and an empty `pr` input. The Action builds once and attaches only to a draft, with no replacement or publication.
5. Verify exact EXE filename, clean full source identity, size, SHA-256, build manifest and downloadable draft assets. Provide that exact download to the owner.
6. Wait for owner Windows smoke acceptance and explicit publication approval. Publish the existing accepted draft without rebuilding, then verify public state, tag and assets.

No tag, Action run, draft or CI result alone is a shipped release.
