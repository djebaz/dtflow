# DTFlow 6.4.0

2026-11-16. Changes since [6.3.0](v6.3.0.md).

## Highlights

- **Download LoRAs from Civitai:** browse models or paste links/IDs, choose exact versions/files, and convert into your managed library. Browse adds saved family/tag filters, seven sort choices and independent AND/OR controls. F9 opens Downloads.
- **Quantize managed F16 LoRAs to q8p:** per-row actions in Connection → Custom LoRAs keep the original, retain a separate compressed copy and offer Prepare afterward. CPU workers are auto-detected, with elapsed/ETA progress; CLI and a separate Colab notebook are also available.
- **Manage DT+ storage:** Connection shows selected-key headroom; storage inspection/deletion and explicit Re-Prepare recovery keep your Prepare draft open.

## Improvements and fixes

- Downloads can optionally auto-prepare after conversion when explicitly enabled. Prepared status is restored from selected-key local confirmations; startup does not repeat browsing or downloading.
- Browse uses bounded cursor requests, manual continuation for sparse results and version/file merging across duplicate models. Keywords use full-text search only; explicit tag pills provide tag filters. Independent streams do not guarantee a globally sorted result.
- Prepare reuses eligible verified conversions across converter versions without overwriting old accepted assets. Training metadata and declared trigger suggestions remain separate from conversion decisions.
- Selected custom LoRAs are verified/restored before generation; a missing required local copy stops submission instead of silently omitting the LoRA. Key changes invalidate stale storage hints.
- Fix malformed-alpha rejection, original-layout Krea 2 conversion mapping, abandoned conversion-staging cleanup, the Prepare hashing-pause callback, partial-failure feedback and overlay cleanup. Connection sections and managed-library actions are clearer; Logs filters fit narrow windows.

## Upgrade and compatibility

- Back up the full state directory and outputs. Execution schema remains **9** and the LoRA asset registry remains **6**, as in 6.3.0; incompatible older registries are refused, not silently reset. Use a pre-upgrade backup for downgrade.
- q8p writing is experimental and accepts supported raw F16 Krea 2, Z Image and SDXL Base inputs. Owner smoke covers selected CPU workflows, not universal model quality or iOS/GPU equivalence. The optional Colab GPU path uses approximate clustering.
- Source installs need `uv sync --locked --group quantization` for q8p; the Windows build includes that dependency. Pillow 13 and the older-CPU NumPy 2.3.5 pin remain unchanged.
