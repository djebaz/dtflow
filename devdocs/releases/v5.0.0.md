# DTFlow 5.0.0

Published: [2026-10-19](https://github.com/djebaz/dtflow/releases/tag/v5.0.0). The preparation-time evidence and acceptance boundaries below are historical records, not a new certification of the published artifact.

## Highlights

- **Inpaint**, local smart person/part selection and paused edit queues, with shared preparation and durable source/mask inputs.
- Reworked **Images** browsing with hybrid scrolling/page chips, incremental preparation/mounting and bounded thumbnail caching. Defaults are **20 images per batch and at most 100 mounted cards**.
- Explicit Trash/permanent-delete controls, per-runtime export destinations and guarded Windows/WSL1 browsing and original-file access.
- Native **Logs** workspace backed by structured JSONL diagnostics, with session-wide filtering/sorting, details, Follow and explicit exports.

## Added

- **Logs:** open from the status bar beside Help; select a session, search/filter the whole retained session, sort by source time/event/component/severity or numeric characteristic, and browse bounded Previous/Next pages. Rows provide Details and raw JSON copying; selected/visible copy, matching CSV/JSONL export and raw-file/folder actions are available. Follow preserves surviving selection. Displayed timing chips round to whole milliseconds without changing raw/filter/sort/export precision. [PR #105](https://github.com/djebaz/dtflow/pull/105).
- **Inpaint:** Source/Mask/Result views, Paint/Select tools, undo/redo, strength, Keep-outside, Grow/Feather, live mask feedback and Use result as source. Edit image prepares source/mask on a worker and dispatches through the dedicated owner-probe path; cloud edits can upload data and consume credits. Generate mode, source location and editor settings are remembered, but masks/history are not restored. This does not claim general checkpoint compatibility. [PR #64](https://github.com/djebaz/dtflow/pull/64).
- **Local selection models:** owner-selected ONNX files support person, body/clothes and part masks; an optional face detector refines face/skin separation. Model paths/checksums are recorded; models are neither downloaded automatically nor bundled, and quality depends on the supplied models. The standalone CPU mask tool remains separate development tooling. [PR #63](https://github.com/djebaz/dtflow/pull/63), [PR #64](https://github.com/djebaz/dtflow/pull/64).
- **Queued edits:** Create queue in Inpaint mode stages immutable, hash-verified source/mask inputs and creates a paused queue. Pair/Cross planning can vary strength; image size cannot vary in that edit plan. Start uses the shared image-operation path, preserving unknown-outcome/no-replay rules. Generic configuration and CLI generation remain txt2img-only; dedicated edit probes remain explicit. [PR #66](https://github.com/djebaz/dtflow/pull/66).
- **Removal and recovery:** Images offers separate Trash and irreversible Delete modes, with fresh per-operation consent and no permanent-delete fallback. Managed edit raw/final files have separate ledger outcomes; ambiguous results remain uncertain and are not replayed. Verified missing originals can be hidden through a durable absent outcome without claiming physical deletion. A committed browsing snapshot keeps Images readable during live-store failures, with an explicit source timestamp and persistent recovery warning; snapshots never authorize mutations/export. [PR #76](https://github.com/djebaz/dtflow/pull/76).
- **Developer tools:** Windows UIA gallery smoke/tuning and Grid `-ml/-mc` matrices observe real visible positions, continuous down/back wheel journeys, view/fullscreen/thumbnail controls and clean-trial exclusions. Output goes under `gallery_bench_smoke/MMddHHmm/`; rankings remain provisional without repeatability. Consumers use structured diagnostics after #105, not automatic gallery CSV. [PR #104](https://github.com/djebaz/dtflow/pull/104), [PR #105](https://github.com/djebaz/dtflow/pull/105).

## Changed

- **One diagnostic stream:** new sessions write rotated UTF-8 JSONL instead of text plus automatic gallery CSV. Typed events retain source timestamps, severity, numeric values and correlation; admission, rejection/loss and closure evidence are explicit. A Qt-free reader serves the viewer, explicit exports and benchmark consumers. Logging failures never retry generation. Historical text/CSV is left untouched and is not automatically converted or accepted as new-format evidence. [PR #105](https://github.com/djebaz/dtflow/pull/105).
- **Images:** filters/sort restart Grid/List at page 1; page chips reflect the visible batch and adjacent reads/preparation/mounting preserve browsing anchors. Source `-ml/--load` and `-mc/--cards` remain overrides, with whole-batch card-cap rounding and bounded reads. Thumbnail cache uses 600 px JPEG 85 by default, WebP 80 by source option, and WebP for alpha; publication is asynchronous. This is not a gallery model/view rewrite or a measured zero-stall guarantee. [PR #89](https://github.com/djebaz/dtflow/pull/89), [PR #92](https://github.com/djebaz/dtflow/pull/92), [PR #95](https://github.com/djebaz/dtflow/pull/95), [PR #102](https://github.com/djebaz/dtflow/pull/102).
- **Windows/WSL1:** verified drive aliases preserve recorded paths; original-file access uses the shared Windows lock/helper boundary where required. Export destinations are remembered separately per runtime. Saved-request reuse, model-readiness checks and desktop opening use worker-side validation; WSL external image opening uses the Windows file association through PowerShell 7, while folders use Explorer. A launched process is not proof that a viewer appeared. [PR #75](https://github.com/djebaz/dtflow/pull/75), [PR #76](https://github.com/djebaz/dtflow/pull/76), [PR #85](https://github.com/djebaz/dtflow/pull/85).
- **Development/CI:** reproducible agent setup/readiness guidance, dependency updates, deterministic temporary image fixtures, expanded offline Qt state definitions and parallel pytest execution. Detailed attribution and CI review requirements are in the [release preparation plan](../plans/2026-10-19-release-5.0.0.md).

## Upgrade and compatibility

- Stop all DTFlow instances and back up the complete durable state and outputs before upgrading. Execution DB schema 3 migrates supported older txt2img history with consistent backups; resolved requests/attempt metadata use version 2. Unsupported/malformed state fails closed. The removal ledger is schema 2; export preferences become schema 2 on save, and older applications refuse that upgraded preferences file. Follow the [runtime layout](../architecture/runtime-layout.md) and [image-operation contracts](../architecture/image-operations.md).
- Downgrade is not an in-place reverse migration. Preserve the pre-upgrade backup; do not open unsupported new state with an older executable or replay uncertain attempts to recreate missing results. Keep original output files and edit-input evidence together with their state.
- The new diagnostic format is intentionally incompatible with old text/CSV readers. Keep historical logs if needed; automatic JSONL retention does not prune them. Log records are evidence, not the durable attempt store or proof of successful generation.
- The 5.0.0 version is owner-selected; it does not declare every provisional roadmap gate complete or make every image-operation/backend/model combination supported.
- The owner confirms ONNX selection compatibility on older CPUs. This confirmation is not a blanket guarantee for all models or hardware, nor acceptance of the exact final 5.0.0 executable.

## Known limitations and acceptance

- **Logs:** end-to-end memory-budget enforcement and export cancellation remain [#106](https://github.com/djebaz/dtflow/issues/106). Windows fault replay, storage/benchmark parity and policy evidence remain [#107](https://github.com/djebaz/dtflow/issues/107). UI differences remain [#108](https://github.com/djebaz/dtflow/issues/108): separate component/event header sort targets, exact matching pending-arrival count, a separate empty-state panel and outside-click inspector dismissal. Component sorting is available through More filters; Refresh currently indicates new evidence without an exact count. Do not describe this delivery as full mockup or acceptance completion.
- **Gallery/cache:** thumbnail eviction is entry-count based, not a byte budget; queued writes can republish after removal cleanup and oversized legacy flat caches have separate cleanup limits. Larger `-ml/-mc` startup latency and remaining stalls are not resolved by the benchmark tooling. See the [gallery follow-up limits](../plans/2026-10-17-images-hybrid-pagination.md).
- **Cross-runtime:** do not run concurrent Windows/WSL state writers. Unverified WSL2 Windows-drive mounts refuse original-touching operations; use WSL-native state or wait for [#77](https://github.com/djebaz/dtflow/issues/77). Read aliases alone never authorize deletion. A remote-completed generation can still fail local saving, leaving absent/partial files and `save_failed`; generating again may incur charges. There is no automatic output recovery.
- **Image editing:** owner probes are scoped evidence, not a compatibility catalogue. Supplied selection-model quality, source normalization/fit/compositing and individual checkpoint/backend behavior retain their documented limits. No model weights ship with this release.
- **Release acceptance:** the exact final clean Windows EXE still requires owner acceptance. Single-run benchmark leaders are not accepted tuning defaults. Detailed PR attribution, historical CI/owner evidence and preparation-only verification are retained in the [release preparation plan](../plans/2026-10-19-release-5.0.0.md), not represented as final executable acceptance.
