# DTFlow 6.5.1

Prepared 2026-11-25. Changes since [6.5.0](v6.5.0.md).

## Highlights

- **LoRA work no longer waits in line.** Downloads, conversions and DT+ Prepare for independent LoRAs can now proceed together instead of one at a time.
- **Safer LoRA and settings handling.** Converted checkpoints are never overwritten, retained files survive source cleanup and interrupted renames, and simultaneous settings changes no longer overwrite each other.
- **More dependable queues and cancellation.** Cancelled runs keep what they already saved, workflows keep their finished outcome across a restart, and videos waiting at the provider call limit can start when a slot frees.

## Added

## Changed

- Independent LoRA downloads, conversions and DT+ Prepare can run together. When they compete for the same file, work visibly waits and resumes on its own. Retained files and their upload receipts stay protected. Three simultaneous download transfers are unchanged.
- LoRA conversion publishes the finished checkpoint without ever replacing an existing file of the same name. On non-Windows systems, the destination folder must support hard links.

## Fixed

- Cancelling while a saved image or video is being written now waits for the save to be recorded, so the result appears in history instead of being lost.
- Videos waiting for provider admission can use a free slot when the open-call limit blocks new calls, and a queue item whose claim fails releases its provider slot.
- After a restart, workflows that had already finished keep their recorded outcome instead of being settled again.
- A Script that is cancelled during setup is cleaned up completely, and Script batch intake is checked again after a LoRA recovery.
- Cancelling a download while Retry is still looking it up stops it before any transfer begins.
- Retained LoRA checkpoints stay in place until their downloaded source has been cleaned up. Interrupted renames restore a file only when its size and checksum match the recorded one.
- Changes to different settings made at the same moment no longer overwrite one another.
- Non-finite LoRA conversion scales are rejected, and out-of-range numbers in workflows are reported as validation errors.
- The queue template library limit counts the bytes actually stored.

## Upgrade and compatibility

- Close DTFlow and back up its complete state directory and original outputs before upgrading. Execution-state schema remains **9**, the LoRA registry remains **6**, pose-template libraries remain schema **1** and pose recipes version **2**. No data migration is involved.
- No new features or settings. Verified pose guidance and video limits from 6.5.0 are unchanged.
