# DTFlow 6.4.1

2026-11-16. Changes since [6.4.0](v6.4.0.md).

## Improvements and fixes

- **LoRA controls:** a taller selected-LoRA list with per-row weight controls; weight sliders and spin boxes share 0.05 mouse-wheel steps.
- **Queue concurrency:** DT+ queues use the Connection page's default each time they start. Separate queue concurrency controls are removed; existing saved queue/recipe limits are ignored.
- **Slideshow New direction:** with Newest first sorting, newly arriving images play next, then playback resumes where it left off.
- **Timing diagnostics:** generation timelines and optional `-time` detail make DT+ waits easier to inspect. Redundant Echo calls are removed from the generation path; no generation-speed guarantee is implied.
- **Quieter logs:** performance measurements now require both `-x` and `-perf`; development logging alone no longer enables them.
- **Download cleanup:** stale Civitai staging files and old unreferenced downloaded sources are cleaned once at startup without blocking the UI. Sources retained for failed/refused conversions are preserved.
- Clarify Civitai credentials and file retention: gated downloads require a permitted token; downloaded sources are deleted after their conversion is retained and verified, but kept when conversion fails or is refused.

## Compatibility

Back up state and outputs before upgrading. Execution schema remains **9** and the LoRA asset registry remains **6**. Runtime dependency versions are unchanged. CLI scripts using a separate queue concurrency option should use the Connection default instead.
