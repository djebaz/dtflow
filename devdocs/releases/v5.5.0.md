# DTFlow 5.5.0

Release preparation: 2026-11-07. Final release-head checks and owner acceptance of the exact Windows executable remain separate from publication.

## Highlights

- Native Workflows chains Generate, Detect face mask, Inpaint, Img2img refine and Save nodes, with per-node settings, saved graphs and branch-level progress.
- Scripts now run through durable queues, with native Setup forms, linked child attempts and optional bounded parallel batches.
- Local DT+ completed-image counters show saved outputs per key and calendar day, without claiming provider quota or blocking generation.

## Added

- Workflows has a library, editable canvas, node inspector and run history, plus strict whole-file import/export using the ComfyUI saved-workflow v1.0 structure and DTFlow contract v1. Each run is one workflow queue item; generated images fan out into independent branches. A missing face pauses only its branch, failures retain saved outputs, and explicit Retry remains bounded. The CLI provides `workflow check` and `workflow queue`. See the [Workflows guide](../guides/workflows.md).
- Detection models can be downloaded after explicit consent from pinned publisher URLs, with SHA-256 and model-contract checks, through Workflows or Generate's Inpaint editor. No models are downloaded during execution.
- The managed Scripts library connects Inspect > Setup > Run Script to one ordinary queue item with durable child attempts, statuses, history and saved results. Nested/repeated forms, native file/folder selection and geometry-only canvas bookkeeping are supported; virtual image pixels and mask generation are not.
- Optional DTFlow-only `pipeline.runBatch` shares existing queue capacity and returns ordered per-job outcomes. The portable Krea2 mixer adds cached LoRA discovery/readiness, a single Setup form, source-scoped preferences and deterministic manual chunks. Missing assets are never implicitly downloaded or uploaded. See [Scripts](../guides/scripts.md) and the [mixer guide](../guides/krea2-mixer.md).
- Connection shows local per-key completed-image estimates; the bottom bar shows the active/all count. Counts use saved UTC evidence and timezone-aware local days, defaulting to Europe/Paris. Older attempts are unattributed; color thresholds are owner-selected guidance, not a verified DT+ allowance.
- Standalone CPU segmentation, depth, promptable-mask and custom SEG/OBB research tools, conversion/rotation diagnostics and review-only annotation helpers are documented under [image experiments](../../tools/images/segmentation-pocs.md). These are not new production model support; private models and datasets are not distributed.

## Changed and fixed

- Connection moves to the far right of the bottom bar; Images uses a shared blue button above inspectors. Hidden pages no longer widen the fixed left rail. Images Grid checkboxes have a larger click target; the grid-position diagnostic is development-mode only.
- Script versions have a compact two-click Remove action, preserving queued source, history and outputs. Setup no longer adds an intermediate preview wizard. Parser-resource failures are distinguished from source syntax errors.
- Parallel script workers recheck admission after awaits and drain admitted work before propagating cancellation or release failures. Existing confirmed cloud LoRA receipts are bound independently of Generate's selection, with fresh account/backend validation at dispatch.
- UI-render tooling uses component-scoped fixture packs, clear incomplete-coverage warnings and individual-image uploads by default. Draft PR renders and expensive docs-only follow-up work are skipped unless explicitly overridden; preview images remain layout evidence only.
- Dependency updates include ONNX Runtime 1.31.1, pytest 9.2.0, pytest-asyncio 1.4.1.post1 and Ruff 0.17.3 (#200). The node-editor runtime uses the Essentials-only Qt baseline; this does not establish legacy-CPU or packaged compatibility.
- Release checks tidy formatting and make paired-array iteration explicit in the standalone depth-region tool; no inference behavior or model support is added.

## Upgrade and compatibility

- Close all instances and back up the full durable state directory and original outputs before upgrading. Do not run simultaneous Windows/WSL SQLite writers or replay uncertain attempts.
- Execution state advances from schema 4 in 5.4.0 to schema 8, covering scripts, child-slot accounting, local key attribution and workflow items. Supported older schemas are backed up before transactional migration. Older applications reject newer state: downgrade only with a separate pre-upgrade backup, never by editing schema numbers or replaying work.
- Queue templates remain version 1; script preferences are independent private authoring state, not automatic resume authority. Back up workflow files and script libraries with the rest of durable state.
- ComfyUI structure compatibility is not execution compatibility: stock ComfyUI workflows do not import, DTFlow nodes do not execute in stock ComfyUI, and a pinned frontend round trip remains unverified.
- The face-mask pipeline currently includes a research-only NVIDIA SegFormer model; its licence is disclosed before download, and replacement is planned. YOLO26n uses AGPL-3.0 and NudeNet 320n uses MIT. No model download or inference is required for release preparation.

## Validation and remaining limits

- Release-head checks and CI are recorded in the [release plan](../plans/2026-11-07-release-5.5.0.md). Earlier source/fake/owner evidence remains scoped to its recorded commit and environment, not acceptance of the release executable.
- Real workflow detectors, model downloads, inpaint/img2img probes, local/DT+ composition and exact Windows/package behavior remain separately gated by the owner's #223 reference smoke. The fake provider cannot validate image-operation execution. Broad script/checkpoint/LoRA compatibility is not claimed.
- Standalone research results do not establish segmentation quality, throughput or memory safety. OpenCV POC reproducibility and model provenance/licensing remain unresolved; an owner-reported large-checkpoint crash has no confirmed cause.
- Existing Logs memory/diagnostic acceptance, startup, platform and gallery follow-ups remain open. Publication requires the dedicated Windows build-and-draft Action, verified artifact identity/checksum and owner smoke acceptance of that exact executable.
