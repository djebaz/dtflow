# DTFlow 6.1.0

Release preparation: 2026-11-08. Changes since [6.0.0](v6.0.0.md).

## Highlights

- Generate and Workflows make each image independently inspectable and retryable in Queues, with explicit generation/saved-image counts and final-image markers.
- Workflows gain global/per-node concurrency, multiple Inpaint/Img2img outputs per input and independent parallel multi-output branches.
- Saved outputs use readable names grouped by queue; existing files stay untouched.
- Detect face mask offers Fast, Balanced and the existing Precise methods, with explicit model-download consent.

## Added

- Workflow global and optional per-node concurrency are saved with the workflow and edited in its inspector. Connection supplies DT+, local and segmentation defaults. The local default of two lanes is owner-selected, not a verified server capacity (#286, PR #287).
- Inpaint and Img2img nodes can produce 1–4 outputs per incoming image. Each output is its own request with seed = node seed + output index; downstream steps run once per output. Independent multiplying nodes retain distinct lineage rather than pairing outputs by variation number (#276, #302; PRs #290, #304).
- Workflow plans show total generations and saved images separately. Planning refuses more than 256 generations across all stages before submitting anything (#278, PR #292).
- Queues lists every workflow image below its run summary, with saved final images labelled "final" and outlined in blue. Counts and progress reflect images instead of one workflow item. Retry on a selected image reruns that step and its descendants without replacing sibling results; summary-row Retry still selects the first failed step (#281, #277; PRs #283, #294, #295).
- Detect face mask adds Fast NudeNet face ellipses and Balanced NudeNet + YOLO person-clipped connected ellipses alongside Precise face-skin/face+hair methods. New nodes default to Balanced with adjustable 1.6× face-box expansion; existing files retain their precise method. Only selected model roles are required, with explicit download consent; downstream Inpaint grow/feather is unchanged (#299, PRs #301, #303).

## Changed

- Generate has one **Images** total. Above one, Generate image creates a queue of single-image items with successive seeds, individual thumbnails/status/Retry and normal up-next scheduling. Inpaint ignores this control. Queue composer readouts distinguish images and requests (#279, PR #289).
- Each workflow Generate output is a separate single-image request with its own seed and failure scope, rather than a provider-native batch (#275, PR #282).
- New output names are readable and retain full attempt identity, with matching JSON sidecars, in one `outputs/queue-<queue id prefix>/` folder per queue. Legacy `outputs/<attempt id>/final-1.png` files remain supported by Images, Queues, Export and Trash/Delete without renaming or migration. See [output layout](../architecture/output-layout.md) (#296, PR #297).

## Fixed

- Retry of one failed Generate image after a workflow ends regenerates only that image and its descendants, not successful siblings; planned counts match the selected scope (PR #300).
- Independent multi-output Inpaint/Img2img nodes on the same images are supported with node-qualified branch identities, replacing the temporary planning refusal (PRs #300, #304).
- Inpaint "Continue without a mask" is reported as succeeded ("passed through, no mask"), with consistent rows, counts, filter chips and logs, and no duplicate final marker. Workflow rows derive operation from node type and show unresolved seeds as unknown rather than zero (PR #300).

## Upgrade and compatibility

- Execution state remains schema 9. Close all instances and back up the full durable state directory and original outputs before upgrading; do not use simultaneous Windows/WSL writers.
- Existing output paths and stored artifact/recycle record shapes are unchanged. Older versions do not recognize newly named outputs as managed originals and refuse Trash/Delete for them.
- Workflow files gain optional concurrency and Inpaint/Img2img output properties; missing values preserve earlier behavior. Older versions reject files with the new output-count property. Older versions rewriting settings drop the optional workflow concurrency defaults.
- Runs with independent parallel multiplying nodes use negative, node-qualified branch integers. Older versions cannot interpret those runs correctly; retain a pre-upgrade backup for downgrade rather than reopening changed state with an older build.
- Existing workflow mask settings keep the Precise method. Fast/Balanced do not require the research-only SegFormer clothes model. Model quality and arbitrary backend/model compatibility are not release guarantees.
