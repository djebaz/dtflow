# DTFlow 6.3.0

Prepared 2026-11-13 from merged changes after [6.2.0](v6.2.0.md), through PR #416. Release candidate; final Windows artifact acceptance and publication are pending.

## Highlights

- **Prepare LoRAs directly from `.safetensors` on Windows:** inspect, convert locally and upload from one editor, with automatic family suggestions and real progress.
- **More readable Logs:** colored compact rows, complete human-readable cell hovers and double-click JSON inspection.
- **Fullscreen Images slideshow**, faster keyboard navigation and clearer LoRA names throughout the desktop.

## Added

- Prepare accepts converted `.ckpt` and source `.safetensors` files. Review names, family and trigger words before **Prepare N ready LoRAs**; conversion starts only after that action. Real phases, transfer bytes, throughput and reliable ETA share the bottom bar, with **Stop after the current file**. Exact earlier conversions are reused; missing or altered retained outputs are rebuilt safely.
- Local converter module CLI supports single files, non-recursive case-insensitive batches, optional family detection and detailed analysis reports. Krea 2, Z Image Turbo, Flux 1 and SD 1.x have sample-specific owner verification; SDXL remains experimental and requires confirmation. See the [converter guide](../guides/lora-ckpt-format.md).
- Custom LoRAs has a compact local library with metadata editing, disk usage and local-copy removal. Managed `ShortName[Tag]` labels leave request identifiers unchanged. Trigger-prefix switches are independent for Generate, Queues, Workflows and Scripts, with an application default.
- Images slideshow loops through filtered outputs at 0.5–8 seconds per image, with prompt/LoRA information, position seeking, direction controls and crossfades. F6 toggles playback; F5 opens Images with Live + Follow, F10 toggles Logs, Ctrl+Tab cycles workspaces and Ctrl+Enter activates the enabled generation/run action.

## Changed

- Logs remembers filters and Compact mode, offers bundled components before their first event and discovers events/characteristics only on explicit Refresh. Compact rows use colored event/key accents; full cell hovers are human-readable, fade in and stay hidden for empty data. Double-click opens JSON details; single-click still selects.
- DT+ key changes automatically check the connection and refresh inventory, preserving the checkpoint when the new key offers it. Local completed-image counts read more efficiently and disclose unavailable/stale evidence instead of showing unverified totals.
- The checkpoint catalogue recognizes 26 additional official DT+ filenames. LoRA diagnostics summarize routine reuse and make restored assets, affected names and recovery failures clearer.

## Fixed

- LoRA compatibility uses file evidence and exact architecture IDs, blocks confirmed mismatches and refuses unversioned prepared overrides. Imported preset/configuration/workflow names relink only to an unambiguous local prepared match; Queue weight sweeps bind each item's effective LoRAs.
- Per-key LoRA receipts remain independent; coordinated recovery and changed-source refresh use current verified content without replaying uncertain transfers. Corrupt checkpoint structures are rejected before upload; retained-copy repair does not overwrite unrelated files.
- Queue status stays fresh during active runs and after leaving Logs. Generate/Edit/Add to queue cannot submit without a model; workflow inspector sizing and repeated LoRA picker opening are corrected.

## Upgrade and compatibility

- **Back up the full state directory and outputs before upgrading.** Execution schema remains 9, but the LoRA asset registry is fresh-state schema 6 with **no legacy migration**. An incompatible registry is refused and left intact. Follow the owner-controlled [clean-start decision](../plans/2026-11-11-canonical-lora-record.md); never delete state containing needed history or outputs. Keep a pre-upgrade backup for downgrade.
- Header-based family suggestions do not guarantee every adapter can convert. Partial Flux 1 adapters can pass source detection yet fail Prepare's stricter output check. SDXL coverage remains incomplete; cross-converter-version reuse is deferred. Unsafe retained names/links fail closed.
- Pillow 13 is used despite the SDK's declared upper bound; NumPy stays pinned to 2.3.5 for the tested older CPU. Earlier smoke is not acceptance of the 6.3.0 executable. Catalogue entries do not establish generation or audio/video support. The native-crash cause remains unproven; closed #308 handed monitoring to [#310](https://github.com/djebaz/dtflow/issues/310).
