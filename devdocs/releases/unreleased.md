# Unreleased

The consolidated changes since 4.0.0 are in [5.0.0 release preparation](v5.0.0.md). This file tracks only changes after that scope; open follow-up issues are not implemented release entries.

## Highlights

## Fixed

- **Queues — owner UI polish:** random controls pack visible dimensions without empty Strength slots, the preview table collapses for invalid/empty plans and restores on valid rows, and only the queue list scrolls in the left rail while Filter and Clear history stay fixed. Offline Queue render asserts all three; packaged Windows acceptance remains separate.

- **Queues — responsive center composer:** action buttons (including Close), random-input pairs, prompt editing and plan-seed controls reflow when the center workspace narrows while both rails remain visible, keeping two compact value pairs per row at intermediate widths. Long summary text and individual fields keep their identity/values. Offline `queues-53`/`queues-54` regression renders added; native Windows DPI acceptance remains pending.

- **Queues — New queue inspector overflow:** model, backend and LoRA identifiers, variation/seed summaries and the explanatory note now wrap within the existing right-rail width instead of extending past the card. The subsequent Windows screenshot exposed vertically clipped LoRA lines even when their width was contained; the inspector now sizes wrapped values against their rendered text height and puts Items below the full LoRA list. Offline renders `queues-52-composer-long-identifiers` and `queues-55-inspector-two-loras` cover text height and geometry at the rail minimum; Windows DPI acceptance is pending.

## Added

- **Random inputs and randomly varied prompts (#128, #129):** Pair/Cross dimensions can draw N distinct random values from their listed values (models, samplers, sizes, LoRA sets, steps, guidance, strengths, LoRA weights) or N random seeds under one recorded **Plan seed** with **Reroll**: the same seed and inputs give the same items, the preview shows the drawn values and each item records `plan.rng_seed` and `plan.random.*` evidence. **Prompt variation** resolves the Generate prompt (`{a|b|c}`, `{2$$a|b|c}`, `{3::a|1::b}` weights, `__list__` wildcards from inline lists or `NAME.txt` files in the state directory's `wildcards` folder) into a seeded random sample or every combination, and *Edit prompts* shuffles the parts or words, drops parts and adds parts, all seeded; each item records its resolved prompt plus template, mutation, wildcard SHA-256 and seed as evidence. Plan files move to `dtflow.queue-plan` version 2 (version 1 still reads) with `random` dimensions, `rng_seed` and prompt `variation`; CLI `queue add` gains `--rng-seed` and `--wildcards-dir`, and `--dry` prints the drawn table. Everything is offline and bounded at 1000 items; the native planner owns prompt variation rather than the Scripts epic. Numeric random ranges (`min`/`max`/`step`) are in plan files only. New renders `queues-48` and `queues-49`. Not yet accepted on Windows.

- **Queue timing comparison:** each settlement records a durable `timing_snapshot` event (elapsed, ETA and projected total), listed in the Events pane as `elapsed + ETA = total`; queue creation now reads `items // max at once`. The estimator moved to `core/queue_eta.py` and accounts for running items' ages; snapshots from before the latest start or Resume are ignored.

- **Queue elapsed time and ETA (#131):** the shared progress overlay and Run tooltip show elapsed wall time since the latest dispatch start. After the first successful item with a usable recorded duration, an explicitly labeled estimate uses the median successful duration, remaining items and observed running-item count. It counts down visibly every second and rebases on observed settlements or changed concurrency/timing evidence; unchanged polls preserve the countdown. Mixed model/size/step plans carry a rough-estimate caveat; the blue progress bar still shows real settled counts only.

- **Relaunch and Retry item (#126, #132):** **Relaunch** in the queue header and the list's context menu creates a new queue from a queue's recorded items, with *Same seeds* or *New seeds* (items that shared a seed share one new seed), for every item or *Only failed items* (failed, cancelled, no result). It starts at once, waits up next behind this window's run, or is saved paused while another process dispatches. **Retry item** in the item panel does the same for one failed, cancelled or no-result item as a one-item queue with its own new attempt. The original queue and attempts are never changed and nothing is replayed; staged Inpaint items reuse their inputs and recorded consent, and a relaunch whose inputs are gone is refused. CLI: `dtflow queue relaunch QUEUE` with `-n/--new-seeds`, `-f/--failed`, `-i/--item N` and `-j/--jobs`, saved paused. The empty state offers **Relaunch last** (the newest queue, same seeds). Relaunched items record their source queue, position and seed choice. Open folder moved beside Retry item on its own row. New renders `queues-42`, `queues-43` and `queues-44`; `queues-17` asserts both actions. Not yet accepted on Windows.
- **One-click Queue from any tab (#135):** an icon-only **Queue** button (stack icon) beside the header Run control and a ▾ dropdown arrow on *Generate image* open the same compact popover. It queues Generate's current request as **Repeat N times** or as the Queues composer's **Composer plan** (Pair/Cross, offered only while that plan is valid), and shows the new queue's Max at once. **Start now** creates the queue and starts it at once; while a queue runs (here or in another process) or a single generation runs, **Add to queue** puts it behind that work to start by itself instead (#133; after a generation, only while this window stays open). Nothing leaves the current tab: progress uses the header Run control and the shared overlay, which also reports the outcome. It uses the same creation and dispatch path as the composer, so the credit, permission and Inpaint owner-probe safeguards are unchanged. New renders `queues-45` to `queues-47`. Not yet accepted on Windows.
- **LoRA sets in Pair/Cross (#124):** a new `loras` plan dimension varies which LoRAs each item uses (each value a list of `{identifier, weight}`, `[]` for none), alongside the existing `lora_weight` sweeps (the two cannot be combined). The composer has a **LoRA sets** chip row using the shared LoRA identifier+weight editor, with *None* and *Generate's LoRAs*; a typed `A: 0.8 + B: 0.4` chip is a set of several. Receipts stay bound only to items whose set includes their LoRA (on the desktop a confirmed custom cloud LoRA named only in a set is bound too), each item records only the receipts it carries, and nothing about compatibility is inferred. Plan files stay `dtflow.queue-plan` version 1.

## Changed

- **Queue composer and New queue placement (#123, #140):** **New queue** moved from the bottom of the left rail to a single **+ New queue** button at the top of the center, visible at every width. It opens a composer in the center in place of the selected queue, with a summary of the Generate base request and *Edit in Generate*. Mode is Repeat (N items, incrementing seeds) or Cross/Pair; models and samplers are picked from the inventory through the shared searchable list, sizes from Generate's size and presets, and steps, guidance and Inpaint strengths with a number box, each as removable chips. The item count and the exact-item preview update while you edit, replacing the Dry run button. Its actions sit on the top row (they wrap onto their own row in a narrow window): **Start now** creates and starts the queue in one step (disabled while this window dispatches or generates, or another process dispatches), **Add to queue** puts it up next behind the running queue, and **Save paused** keeps the previous behavior. The composer has no title. Prompts, seeds and LoRA weights stay typed (LoRA selection is #124); the planner, CLI and plan files are unchanged. While composing, the right column summarizes the new queue (backend, model, LoRAs, items, what varies, seeds, Max at once). The queue header is now a padded card whose details sit on labelled lines (Model, LoRAs with weights, Plan, Backend, Created), and list rows count the LoRAs. Changing Max at once no longer shows a success overlay (refusals still do). New renders `queues-37` to `queues-41`; `queues-03` is now the composer preview. Not yet accepted on Windows.
- **Cloud concurrency and admission (#138):** Max at once, persisted settings, CLI and direct-cloud adapter allow 1–10 (existing default 4). Text-to-image cloud requests reserve 32 MiB per generation within a shared 320 MiB budget; ten client submissions can overlap. A saved cloud concurrency above 4 is rejected by older builds. Image-edit reservations stay conservative; native memory usage and provider-side concurrency remain unverified.
- **Queues header and list (#121, #122):** the selected queue has one header: its prompt as title, model · plan · backend · time below, one status chip (ownership in its tooltip), one primary action that changes with the state (Start, Start next, Pause or Resume), Cancel, Earlier/Later only for a waiting queue, its own **Max at once** and **Remove**. A segmented progress bar shows settled items by outcome, and ✓ ✗ ? – count chips filter the items table. The ownership badge, the sticky message line, the separate Start/Pause/Resume buttons and the left-rail Dispatch policy card are gone; action outcomes go to the shared bottom overlay, and the shared cloud default moves to **Max at once** under **New queue**. The queue list uses the rail height and groups rich rows (prompt, model, plan summary, backend, time, status chip, mini progress) as Running, Up next, Paused and History with a text filter. **Remove** (header or context menu, inline confirmation) deletes one paused, finished or cancelled queue record; **Clear history** now keeps paused queues. Neither touches attempts or outputs. The list reads summaries only (state counts and the first item, with the item-variation scan done once per queue), items and events are read for the selected queue alone, and the list polls lightly while the tab is visible. Refresh is an icon. New renders `queues-26` to `queues-30`, and `queues-05` is now the Remove confirmation. Not yet accepted on Windows.
- **Edit while a run is active, and up next with auto-play (#133, #125):** Generate, LoRA, inventory refresh and the Inpaint editor (source, mask, mode switch) stay editable during a generation or queue run; a running request keeps the snapshot taken when it started, and the Effective request says so. Opening an Images edit no longer waits for the run. **Create queue** works while a queue runs (a paused queue saved over a short shared connection; CLI `queue add` likewise). While the window dispatches, **Start next** puts a paused queue *up next*; up-next queues start by themselves in order when the running queue finishes or is cancelled, **Earlier**/**Later** reorder them and **Pause** takes one out. **Generate** during a queue run adds a one-item up-next queue. Cancel on a waiting queue (desktop, or CLI `queue cancel`/`queue pause`) applies at once. Picking and starting the next queue is one atomic step, and joining the order needs a live dispatch owner (an advertised `queue_dispatch` row), so nothing is left waiting for nobody. Auto-play stops when dispatch ends (failure, local stop, close); waiting queues then return to paused, as they do at every new owner open, so nothing auto-starts after a restart. The CLI has no enqueue/reorder command and `queue start` runs only the named queue. Execution DB schema 4 adds the `queued` state and the up-next order; opening a v1–v3 database writes a fresh `attempts.pre-v4-from-v<old>-<uuid>.sqlite3` backup first, and older DTFlow versions refuse schema 4. Not yet rendered or accepted on Windows.
- **Queues: unknown outcomes no longer block (#132, #120):** an item whose final result never arrives is settled as `unknown` (shown as *no result*, with a note that it most likely failed), releases its reservation and does not block its queue, other queues or the backend; it is still never replayed automatically. The Acknowledge/Override control, the always-visible Uncertainty card and the `blocked` queue status are removed (the card is now an *Outcome* note shown only for no-result and failed items), `queue override` is a hidden, deprecated no-op that prints a note and records nothing, and `queue start` exits `3` instead of `4` when items are unknown; the activity list says *no result* for unknown items. On local Draw Things the next item may wait behind an abandoned job, which is accepted. An older DTFlow opening the same state treats existing unknown items as blocking again. Cancel no longer asks for confirmation. Existing unknown rows become non-blocking without migration. Part of the Queues redesign epic #130; not yet rendered or accepted on Windows.
- **Logs workspace presentation (#108):** the event column header paints separate `COMPONENT` and `EVENT` sort targets in one section, and each event cell shows its component above the event chip; with Follow off, Refresh shows the number of matching arrivals since the shown snapshot (`Refresh (3 new)`, or `Refresh (0 new · incomplete)` when evidence is incomplete even with no matches) through a single bounded background count; empty sessions and filters with no matches show a panel in place of the table; a primary click elsewhere in Logs collapses the details pane without consuming the click, while splitter, scroll bar and row-action presses keep it open. Refresh and Follow carry icons, and the Refresh icon turns while a page read (including a Follow refresh) runs; the session selector has a bounded width with a shorter `#N · time · short id` label and the full id in its tooltip. While Logs is open, no header navigation tab stays selected; closing Logs reselects the previous page's tab. Not yet rendered or accepted on Windows.

## Fixed

- **Right panel overflow:** the right column on Generate and Queues no longer runs past its width with a horizontal scroll bar. The shared right column was sized to its widest page on every tab (the Queues *Selected item* card), so it now follows only the shown page and never scrolls sideways; Open folder and Retry item span the full card width and a long backend name wraps.

- **Composer mode dropdown:** clicking *Repeat*, *Cross* or *Pair* in the Queues composer's mode list now selects it. The popup list had been disabled with the page's other preview controls, so a click closed it without choosing (the keyboard worked). The header Queue and Run icons also no longer shift when the logo is hovered.

- **Queue recovery and selection:** interrupted running queues offer Resume after their dispatch owner stops; taking over still acquires the execution lock and preserves uncertain outcomes. Selecting a newly created queue clears the previous queue's outcome filters and immediately loads its items, including while idle polling is stopped.

- **Logs export (#111):** exporting the current, still-growing session works: the export pins the session as it stood at start, follows rotation renames and leaves later appends out. Unsealed or incomplete sessions export with their evidence state and reasons disclosed instead of being refused. Exports show progress with Cancel in the shared bottom overlay, run one at a time, keep running and report their outcome after leaving Logs, and summarize the result as file name, record count and source state instead of a raw manifest. A reader pass no longer treats appends to the same files as a snapshot change, so busy live sessions no longer read as incomplete for that reason. Export selection now rejects a conservative candidate byte-budget overrun explicitly (no partial success); full pipeline memory budgets remain #106. Not yet accepted on Windows.
