## Changed

- **Edit while a run is active, and up next with auto-play (#133, #125):** Generate, LoRA, inventory refresh and the Inpaint editor (source, mask, mode switch) stay editable during a generation or queue run; a running request keeps the snapshot taken when it started, and the Effective request says so. Opening an Images edit no longer waits for the run. **Create queue** works while a queue runs (a paused queue saved over a short shared connection; CLI `queue add` likewise). While the window dispatches, **Start next** puts a paused queue *up next*; up-next queues start by themselves in order when the running queue finishes or is cancelled, **Earlier**/**Later** reorder them and **Pause** takes one out. **Generate** during a queue run adds a one-item up-next queue. Cancel on a waiting queue (desktop, or CLI `queue cancel`/`queue pause`) applies at once. Picking and starting the next queue is one atomic step, and joining the order needs a live dispatch owner (an advertised `queue_dispatch` row), so nothing is left waiting for nobody. Auto-play stops when dispatch ends (failure, local stop, close); waiting queues then return to paused, as they do at every new owner open, so nothing auto-starts after a restart. The CLI has no enqueue/reorder command and `queue start` runs only the named queue. Execution DB schema 4 adds the `queued` state and the up-next order; opening a v1–v3 database writes a fresh `attempts.pre-v4-from-v<old>-<uuid>.sqlite3` backup first, and older DTFlow versions refuse schema 4. Not yet rendered or accepted on Windows.
- **Queues: unknown outcomes no longer block (#132, #120):** an item whose final result never arrives is settled as `unknown` (shown as *no result*, with a note that it most likely failed), releases its reservation and does not block its queue, other queues or the backend; it is still never replayed automatically. The Acknowledge/Override control, the always-visible Uncertainty card and the `blocked` queue status are removed (the card is now an *Outcome* note shown only for no-result and failed items), `queue override` is a hidden, deprecated no-op that prints a note and records nothing, and `queue start` exits `3` instead of `4` when items are unknown; the activity list says *no result* for unknown items. On local Draw Things the next item may wait behind an abandoned job, which is accepted. An older DTFlow opening the same state treats existing unknown items as blocking again. Cancel no longer asks for confirmation. Existing unknown rows become non-blocking without migration. Part of the Queues redesign epic #130; not yet rendered or accepted on Windows.
- **Logs workspace presentation (#108):** the event column header paints separate `COMPONENT` and `EVENT` sort targets in one section, and each event cell shows its component above the event chip; with Follow off, Refresh shows the number of matching arrivals since the shown snapshot (`Refresh (3 new)`, or `Refresh (0 new · incomplete)` when evidence is incomplete even with no matches) through a single bounded background count; empty sessions and filters with no matches show a panel in place of the table; a primary click elsewhere in Logs collapses the details pane without consuming the click, while splitter, scroll bar and row-action presses keep it open. Refresh and Follow carry icons, and the Refresh icon turns while a page read (including a Follow refresh) runs; the session selector has a bounded width with a shorter `#N · time · short id` label and the full id in its tooltip. While Logs is open, no header navigation tab stays selected; closing Logs reselects the previous page's tab. Not yet rendered or accepted on Windows.

## Fixed

- **Logs export (#111):** exporting the current, still-growing session works: the export pins the session as it stood at start, follows rotation renames and leaves later appends out. Unsealed or incomplete sessions export with their evidence state and reasons disclosed instead of being refused. Exports show progress with Cancel in the shared bottom overlay, run one at a time, keep running and report their outcome after leaving Logs, and summarize the result as file name, record count and source state instead of a raw manifest. A reader pass no longer treats appends to the same files as a snapshot change, so busy live sessions no longer read as incomplete for that reason. Export selection now rejects a conservative candidate byte-budget overrun explicitly (no partial success); full pipeline memory budgets remain #106. Not yet accepted on Windows.
