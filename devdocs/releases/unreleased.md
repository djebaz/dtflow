# Unreleased

Changes through 6.4.1 are consolidated in [DTFlow 6.4.1](v6.4.1.md). The published GitHub release and its artifact identity establish availability.

## Highlights

## Added

- **Generate shows a grid of results for several items (PR #567, closes #560, epic #554):** when Generate starts a Repeat of two or more items (Images above 1, or Repeat in the Queue popover), its output panel shows one tile per item, filling in as each is saved, with a small preview while an image is running, a saved video's poster, hover to enlarge, and a click that opens that exact result in Images. A single image, edit, pose or video keeps its existing viewer. Previews are only decoded for tiles you can see, and not at all while Generate is hidden. Owner-reported Windows smoke with real batches (tiles, click-through to Images Detail, newest run shown, multi-video tiles kept after switching tabs), plus source, test-suite and Fake-backend evidence; provider preview CPU and memory were not measured.

- **Local video encoding settings (PR #553, closes #550):** Connection has a video encoding card with the maximum number of simultaneous local encoders (Unlimited or 1–10) and FFmpeg threads per encoder (Auto or 1–16); changes apply to the next encoder and are saved. Received frames are first kept on disk, so downloading never waits for FFmpeg, and a clip waits for a free encoder with a visible "Waiting for local encoder" phase. The old total video timeout is gone: only receiving from the provider has a time limit (1,800 s), and local encoding is bounded by FFmpeg's own timeouts. Stop interrupts a long local encode, and a failed or stopped item removes its intermediate files. Static, source and full test-suite evidence plus an owner six-video Windows smoke; cancellation during encoding and a full disk were not exercised on Windows.

- Supported DT+ video requests can use the existing Queue Repeat/composer and rolling dispatcher, up to Connection's 1–10 default, with durable source copies, independent MP4/poster/sidecar outcomes and per-item live phases. Shared video admission bounds pipeline count, payload queues and logical disk reservations; missing tools/storage refuse before submission. Video retries remain manual. Twenty concurrent clips, video templates and Scripts/Workflows are outside this slice (PR #547, refs #546; static/source evidence only, owner Windows/provider concurrency acceptance pending).

- **Video companion lifecycle (PR #535, refs #530):** Images Trash/Delete now include sidecar-proven MP4 clips with their posters using the existing managed-original ledger and partial-failure reporting. Mixed Images exports copy original MP4s without re-encoding while still converting images to JPEG; missing/unverifiable clips fail visibly instead of exporting the poster. Shared export controls now label saved videos correctly. Sidecars and generation history remain retained; automatic restore is not supported. Source-reviewed only; Windows deletion/export smoke pending.

- **Images video playback:** Videos in Detail now have a compact single-row toolbar with an expanding seek bar and blue playhead marker, Play/Pause, elapsed/total time, mute, restart, Autoplay and Close. Click the poster/video or use K/S for Play/Pause; W/X seek one second, numeric keypad 4/6 seek ten seconds, keypad 0 restarts, and M mutes. Ordinary Left/Right browse outputs. **Autoplay** is off by default and saved in viewer preferences; when enabled, opening or returning to a video starts playback at 0:00. Grid/List and the filmstrip show video durations, and Detail shows saved/probed media facts. Still-image behavior is unchanged (PR #534, closes #531; owner-accepted Windows UX, Preview passed on the code head; bundled playback remains #529).

- Windows packaging embeds pinned FFmpeg/ffprobe using imageio-mini (FFmpeg 4.2.2 + minimal FFprobe 7.1) as the Windows workflow default following owner video-generation smoke; Gyan 8.1.2 remains the standalone CLI builder default, and TAS-FFMPEG 8.1.2, Unpins 8.1.2-1 and imageio + Gyan probe remain explicitly selectable for comparison, without UPX. The worker checks readiness before paid video submission. Each variant records its publisher checksum, licenses and provenance manifest (#529, PR #533; the imageio build measured 174,997,706 bytes, imageio-mini measured 140,140,874 bytes with owner-reported successful Windows video generation, and full source-delivery and detailed playback/probe review remain pending).
- Pose-enabled Queue drafts expose ControlNet checkpoint/quantization, strength, control force and Apply from/to, with a read-only map preview and explicit replacement by another prepared body map. Edits remain local to the draft; template Save/Update remains explicit, and photo extraction stays in Generate (PR #522, refs #515; owner-reported functional acceptance and automatic CI/Preview passed on `c22d8cd8`; UI/UX polish is tracked separately in #528, not broad DPI/packaged acceptance).
- Controlnet pose generations can be queued with **Images N**, **Repeat**, and **New queue plan** (DT+ Cloud only): each item gets a separate seed and shares one staged pose map and Union control. Queue creation stays local; Start sends the map and may consume credits (PR #513, refs #505; owner-reported Windows smoke completed).
- Local pose templates retain a bounded body map and exact control settings from a captured Controlnet or recorded queue draft, without execution-file dependencies or upload consent. Loading changes only the composer; creating/starting the queue keeps the existing DT+ checks and consent (PR #513; owner-reported template Save/Load smoke completed).
- Generate has a Controlnet mode: generate from a photograph or a body map with a Union Pro 1.0 pose control on DT+ Cloud, with control force and apply from / to, a person pick for photographs, omitted joints named under the map and a Source / Pose / Result canvas. Only `flux_1_dev_q5p` with Union Pro 1.0 q5p at 0.7 is verified; other FLUX.1 checkpoints show "not verified". Gallery Use settings restores the pose.
- Connection → Custom LoRAs lists managed LoRAs that have no retained local copy and lets you remove their local registry records after confirmation; remote DT+ storage and saved results are unchanged (#511).

## Changed

- **One progress bar for every generation mode (#564):** the status-bar Activity Bar now summarizes every active queue at once, including a queue running in another process and a script or workflow as one item. Each queue has its own colour in a growing segmented fill, one line shows settled/total, failures and, where they fit, sampling and receiving counters, and Stop names the queue it stops when several run. Elapsed time covers the whole activity period and the ETA is approximate when it is derived from the fill. The header progress ring (and its Start/Pause/Resume button) is removed; those controls stay in Queues. Queue-success notices last three seconds and a click outside any overlay notice dismisses it. The main window's minimum width is now 1000 px.

- **Queue provider slots (#557, epic #554):** the DT+ concurrency setting now limits generations that DT+ is sampling, shared by every queue, Script and Workflow. An image that has finished sampling no longer holds its slot while it downloads and saves, so the next item starts immediately; calls past sampling stay bounded at twice the limit. Queues claim an item only when a slot is free, so no claimed item waits idle, older queues come first, a Pause or Cancel is checked again just before an item is marked sent (an unsent item returns to pending, its prepared attempt kept as cancelled; an automatic retry waits for a slot after its delay and is not sent if the queue was paused), the next Up next queue can start early whenever a running queue cannot use free capacity (for example while it repairs LoRAs), and a settled failed item's log record now names its recorded failure. Video items keep #550's local limits and free the slot once the clip is received. Source and test-suite evidence only; DT+ utilization on Windows with real credits is not yet observed.
- **Generate runs as a one-item queue (#558, #559, epic #554):** every Generate click (an image, an Inpaint or Img2Img edit, a Controlnet pose image or one video) now creates one queue item that appears in Queues history and takes the next free provider slot ahead of queue work that has not been sent yet, also while a queue is running. Generate still shows progress, live previews, the result, Stop and Retry in place, and says *Waiting for an available generation slot* while all slots are busy. You can click Generate again while earlier clicks wait or run: each is its own queue and Generate shows the latest. The header progress bar follows the shared queue run, and while the provider is silent Generate counts the seconds since its last report. Stop in Generate affects only the request it shows; Retry reruns the same item as a new attempt.
- Windows source runs now use the same staged FFmpeg/FFprobe as the packaged build (stage them once with `uv run python tools/packaging/ffmpeg_bundle.py`) instead of whatever is on PATH; the readiness message says when they are missing (PR #551, closes #549; owner Windows run on DT+ Cloud saved a video with audio).
- Video queues distinguish local resource waiting from preparation, summarize concurrent phases compactly, retain start images atomically and report MP4 size caps explicitly. Video processing uses a dedicated worker pool; pre-submit disk rechecks no longer double-charge other clips' reservations. Source retention remains indefinite, with no automatic orphan cleanup (PR #547; source/static-reviewed, owner runtime acceptance pending).

- The Queues composer shows editable **Fixed LoRAs** independently of LoRA weight sweeps and lists available models across inventory families in **Add model** (PR #510, refs #507).
- The pose detector is now YOLO26n-pose (reinstall it once from the Pose guidance card or the CLI).
- The sampler list offers every sampler in all Generate modes, sorted A to Z.
- The Generate mode (Text to image, Inpaint, Controlnet, Scripts) is remembered between launches.
- Scripts mode has a Controlnet tab that returns to Generate in Controlnet mode (#511).

## Fixed

- **Deferred saved editor inputs (PR #556, refs #555):** A remembered ControlNet photo/pose map no longer starts ONNX detection or map fitting while DTFlow opens on Connection; the saved pose automatically restores when Generate → ControlNet becomes visible (owner Windows confirmation). The separate remembered Inpaint source no longer triggers “Load source image” at startup: it loads on first visible Generate → Inpaint entry, retaining its path if the app closes sooner. The Inpaint extension is source-reviewed only, pending a quick no-credit Windows navigation check.

- Video queue admission no longer reserves a fixed 1.5 GiB per clip on a shared drive: derived output/temporary charges are 300/600 MiB, and items wait when other active clips hold disk budget. This addresses owner smoke in which 12 GiB free admitted only seven of ten clips; ten-clip validation of the refined policy remains pending (PR #547, refs #546).

- Generate's Video controls now use the shared section-card structure and token-backed button/crop states, with explicit 12 px body padding, one control row (Duration/readout left, cover-filled source thumbnail/red × badge right) and no reserved blank warning height. Crop inspection also follows hover, keyboard focus and edits on Width/Height. Video draft validation refreshes Generate availability, and second-pass progress no longer retains first-pass counts (PR #545, refs #540; owner confirmed all ACs passed and exact-head CI/Preview succeeded on `7f15b25f` before squash merge `39369d30`; not new packaged-release acceptance).

- The desktop Connection and Generate provider selectors no longer offer the internal Fake backend. Previously saved Fake selections require an explicit choice of Local Draw Things or DT+ Cloud before generation; existing Fake data and CLI/test/preview support are preserved (PR #519, refs #518; owner-reported manual testing and CI/Preview passed on the preceding code commit).
- Documentation examples no longer embed owner-specific workstation paths. The WSL X11 helper derives the current Windows application-data directory, selected WSL user's home and its own checkout path instead of hard-coding an account; this does not remove older Git history or Action logs. Static validation only; the helper was not executed.
- Repository path/PII scanning now supports the Action's existing check presets and extension selection using the newer shared scanner; scanner failures are no longer summarized as a clean scan. These are heuristic findings, not proof of private-data exposure; the updated Action has not been rerun by the agent.
- Controlnet → New queue plan explicitly refreshes the current pose map/controls through Use Generate settings' pose-only mode, preserving the Queue draft's base settings and plan variations instead of reusing a stale composer pose. The composer summary and queued Parameters tooltip expose exact pose checkpoint/quantization, strength, force and range (PR #513; owner-reported Windows retest confirmed non-default pose settings are preserved).
- Generate/Retry can hand a pose to the queue-behind creation path without an argument-count or queue-ID unpacking error. Pose templates own their maps instead of retaining staged execution identities (PR #513; source-reviewed; owner smoke confirmed queue-behind and template workflows).
- Queued pose items preserve their control and retained map across dispatch, Relaunch, Retry and Edit as new. Missing staged inputs fail explicitly instead of falling back to unguided text-to-image generation (PR #513; owner smoke confirmed pose dispatch, Relaunch, Retry and Edit as new; missing/altered-map failure not directly exercised).
- **Edit as new queue…** no longer silently carries unwanted fixed LoRAs from older plans; reconstructed drafts and manually removed fixed LoRAs discard obsolete DT+ receipt bindings without changing the source queue (PR #510).
- Startup always opens on Connection; selecting Generate later opens its remembered sub-mode, including Scripts, without a startup redirect (#511).
- Removing a registry-only LoRA updates the affected row without rescanning all retained LoRAs or rebuilding the entire table (#511).

## Upgrade and compatibility

- Template database schema stays 1; pose recipes use version 2 while existing text-only version-1 recipes still load. Older apps refuse libraries containing v2 recipes without changing them. Existing per-recipe/library limits remain; pose PNGs are additionally limited to 128 KiB before Base64 encoding. No automatic migration, image extraction, upload or queue replay is added.
