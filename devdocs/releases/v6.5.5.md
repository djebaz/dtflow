# DTFlow 6.5.5

Prepared 2026-11-25. Changes since [6.5.1](v6.5.1.md).

## Highlights

- **LoRAs stored on DT+ now show up everywhere.** LoRAs held on your DT+ storage that this computer never prepared appear in Generate, Queues, Workflows and Scripts.
- **Compare LoRA weights in one queue.** A new Cross LoRA weights mode in the Queues composer tries every Fixed LoRA at several weights.
- **Fewer rough edges with presets, scripts and long sessions.** Presets load with the right LoRAs, imports and saves are safer, and Scripts and background work behave better under limits and cancellation.

## Added

- **Cross LoRA weights** in the Queues composer: every Fixed LoRA is taken at 0, 0.5 and 1 and all combinations are created, within the queue size limit. Reopening such a queue returns to the same mode and labels the LoRAs it varied.
- Loading a saved preset can select and remember renamed LoRAs that are already prepared for the selected DT+ key.
- Development-mode source logs record the Git commit and tracked-worktree status when available. The desktop footer and About dialog show the short revision without a `g` prefix, and new executable filenames use the same bare short revision.

## Changed

- Requests with oversized numbers, including inpainting mask feather settings, report validation errors. Presets with unrepresentable guidance or LoRA weights keep those values for re-export.
- The desktop releases its references to background work as soon as that work starts, keeping tracking bounded during long sessions.
- The LoRA Check result lists in full only the LoRAs that need attention; the ones that match are summed up in one line.

## Fixed

- LoRAs stored on DT+ that this computer never prepared now appear in Generate, Queues, Workflows and Scripts, including conventional LoRA checkpoint names that DT+ reports without metadata. DTFlow checks each stored file with DT+ (nothing is uploaded) after reading the selected key's storage, and once per run for your other saved keys. A LoRA held only on another key shows as needing a re-attach on the selected key. Compatible bundled LoRAs that DT+ leaves out stay selectable with availability unconfirmed.
- LoRA names you previously acknowledged, which only have historical missing-key receipts, return to the shared selection pool. Dispatch still checks the selected key.
- Krea 2 intermediate previews now use the correct colours.
- Preset imports keep the existing library if the selected file disappears, and import and save keep the library within its 4 MiB read limit.
- Script analysis applies its time limit to parser startup, and Script files are checked against the 1 MiB limit while they are read.
- Queues created at the same moment from identical script sources no longer conflict over temporary files.
- Cancelling a video while local cleanup is running still frees its encoder slot and removes its temporary files.
- Changing the daily reset timezone preserves unreadable or unsupported preference files and honors the 4 KiB file limit.

## Upgrade and compatibility

- Close DTFlow and back up its complete state directory and original outputs before upgrading. Execution-state schema remains **9**, the LoRA registry remains **6**, pose-template libraries remain schema **1** and pose recipes version **2**. No data migration is involved.
- The executable filename now carries the bare short revision, for example `dtflow-6.5.5-<sha>-windows-x64-…exe`.
