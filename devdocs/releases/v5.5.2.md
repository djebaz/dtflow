# DTFlow 5.5.2

Release preparation: 2026-11-07. Changes since [5.5.0](v5.5.0.md); exact Windows artifact acceptance remains separate from source validation and publication.

## Highlights

- Generate and Queues show meaningful failure reasons and offer Retry with the recorded settings and seed. Queues retries the existing item, preserving previous attempts.
- Generate, Queues, Scripts and Workflows share one bounded automatic retry: at most one retry after five seconds for eligible transient failures, including the narrowly matched owner-approved DT+ INTERNAL no-image case. Other ambiguous outcomes, hard refusals and user stops are not automatically replayed. A retry can consume credits or duplicate a submission.
- Scripts offers Retry or Continue without the failed image and stores each run in its queue item instead of a separate database.

## Changed and fixed

- Script history, linked children, forms and answers are queue-owned. Cross-process form controls are revalidated; headless immediate-run defaults, worker cleanup and late-answer rejection are preserved. `script --run` without `--queue` creates and starts a one-item script queue and reports its queue identity/state.
- Queued image-edit Start supplies consent without redundant per-item bookkeeping. Workflow Stop ends local waiting promptly, without promising remote cancellation.
- Startup browses supported older execution schemas read-only before owner-controlled migration. Queue refresh failures also emit privacy-safe diagnostic warnings.
- Workflows bind existing prepared custom DT+ LoRA receipts independently of Generate, recheck Pause after binding and stop invalid bindings before image submission. Missing-receipt/unknown-availability warnings retain output/node and queue-log details without assuming an unconfirmed LoRA is custom. Historical finished runs retain details without replaying notices. No implicit preparation/upload is added.
- The Workflow canvas supports plain **Delete** for selected nodes and their connected edges through its existing deletion/history path; Ctrl+Z undo is unchanged (#259). Native keyboard acceptance remains separate.
- The bottom-bar local DT+ completed-image estimate refreshes on activity changes outside Connection. It remains saved-evidence accounting, not provider quota or polling.
- Offline CI uses Fast checks for PRs and Full checks on main/manual dispatch. The queue-control check no longer assumes concurrent preparation reaches the backend in FIFO order; durable ordering and outcome checks remain intact.
- Dependabot ignores incompatible Pillow 13 proposals while `drawthings-py` requires Pillow below 13. Actions upload-artifact is updated to 7.0.2.

## Upgrade and compatibility

- Close all instances and back up the full durable state directory and original outputs before upgrading. Do not run simultaneous Windows/WSL SQLite writers or replay uncertain work.
- Execution state advances from schema 8 in 5.5.0 to **schema 9**. Supported older state is backed up before transactional migration; legacy script runs are imported into queue items. The old `script_runs.sqlite3` is left untouched and no longer written. Older builds reject upgraded state; downgrade only using a separate pre-upgrade backup.
- Restart reconciliation interrupts running scripts and keeps unresolved steps unknown rather than replaying them. Queue templates and separate authoring preferences retain their existing contracts.

## Validation and remaining limits

- The [#220 close-out record](../plans/2026-11-07-issue220-closeout.md) separates existing Linux offline evidence from owner-reported Windows schema 9 migration and real DT+ retry smoke. These reports are not acceptance of this release executable. Dedicated schema 8/legacy-ledger to schema 9 regression and exhaustive per-runner live coverage remain gaps.
- Release checks and exact-head GitHub CI are recorded in the [5.5.2 release plan](../plans/2026-11-07-release-5.5.2.md). No local tests or UI renders are run for this preparation, at the owner's request. No new model download, training, inference, upload or provider call is required.
- Broader Workflows/model, Scripts compatibility, research-model licensing, Logs and native Windows/DPI limits in [5.5.0](v5.5.0.md) remain. A possible late database commit after the 60-second write timeout remains a known uncertainty.
- Publication requires the dedicated Windows build-and-draft Action, verified clean artifact identity/checksum and owner smoke acceptance of that exact executable.
