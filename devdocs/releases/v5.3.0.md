# DTFlow 5.3.0

Release preparation: 2026-10-26. Source changes are merged; final release checks and exact Windows executable acceptance are pending. This document is not a publication declaration.

## Highlights

- Faster Windows source startup, a minimal startup splash and a one-shot background connection check.
- Reusable queue recipes, bulk removal of eligible paused queues and better use of free slots between Up-next queues.
- Stable queue-history thumbnails and clearer progress-stage presentation.

## Added

- Save and reload named local text-to-image queue recipes. Search, update, rename and delete recipes with explicit dirty-draft and backend-rebinding consent. Loading changes only the independent composer; it never starts work, switches the connection or uploads assets.
- **Clear paused queues** removes eligible paused queues with pending work immediately, without confirmation. Eligibility is revalidated transactionally and removed/skipped counts are reported. Running, Up-next, blocked, finished and cancelled queues, attempts and saved images are untouched.
- The desktop shows a logo/wordmark splash after Python and Qt initialize. A thin indeterminate segment covers UI imports, then real construction milestones drive the bar; it is not an elapsed-time estimate and can remain static while the GUI thread is busy. The splash closes on the main window's first paint or a bounded fallback, and on startup failure. One-file extraction still happens before the splash can appear.
- Startup checks the restored connection once in the background when configured. The retained indicator reports the last check, not continuous monitoring; startup never generates images or resumes queues.
- Offline startup reports expose phase sample counts and warn about mixed instrumentation schemas. An isolated QLineEdit diagnostic supports font/style comparisons without opening application state or contacting providers.
- The canonical Windows builder supports an optional `--onedir` distribution for startup comparisons. The default release artifact remains the single-file executable; a folder build must be distributed as the entire folder, never its EXE alone.

## Changed

- Windows theme resolution avoids generic font-family fallback lookups, and measured expensive icon-only glyphs use artwork or painted presentation. Form loaders/parenting, shared brand decoding, lazy optional imports and deferred event-filter installation reduce avoidable startup work. Owner source observations fell from 11.1–15.7 seconds to 3.5–4.1 seconds during this work; these are single-machine observations, not controlled cold/warm or packaged benchmarks, and do not establish the splash's performance.
- Connection checking and provider preloading are deferred after the startup milestone. Two owner runs recorded smaller post-load heartbeat gaps; delaying an import does not prove that GIL contention or freezes are eliminated. Startup marks, paint events and first usable interaction remain distinct measurements.
- A free slot may start the next Up-next queue on the same backend once the current queue has claimed its last pending item. Existing combined/backend caps, durable claims and submission ownership still apply. Queues settle in start order; paused, cancelled and different-backend queues do not overlap, and drafted/paused queues are never implicitly started. No measured throughput improvement is claimed.
- Progress presentation distinguishes admitted/preparing work, request submission, backend waiting and observed sampling without inventing percentages. Offline stage and animation lifecycle coverage and preview definitions were extended.

## Fixed

- Queue-history thumbnails and hover previews no longer blink empty during background availability refresh. Failed checks still clear previews; Open in Images still requires fresh availability.
- Changing connection settings or saving/removing a key permits a new check immediately. Retired callbacks cannot replace the newer check's state or unlock its controls.
- Queue coverage checks FIFO at durable admission rather than relying on asynchronous backend arrival order.
- Queue preview fixtures reject late startup reads that could overwrite synthetic state, use complete legacy request records and isolate activity-bar widths from native window-sizing constraints.

## Upgrade and compatibility

- Close other instances and back up the full durable state directory and original outputs before upgrading. Do not run concurrent Windows/WSL SQLite writers or replay uncertain attempts.
- The execution database remains schema 4. The new durable queue-template library has its own version-1 database; it is not disposable cache. Keep state backups when considering a downgrade; older versions do not gain template support.
- Template recipes preserve authoring input rather than execution authority. Legacy queue reconstruction retains its disclosed limits, and loading or editing a recipe does not grant dispatch consent. Credential resolution, provider compatibility and remote cancellation uncertainty remain unchanged.
- See the [build guide](../guides/building.md) for single-file versus folder distribution, disk-space requirements and exact-artifact smoke checks.

## Validation and remaining limits

- Version-only lock consistency and release documentation links were checked during preparation. Release lint/format and offline-suite evidence will be recorded in the release PR; earlier scoped source tests and owner reports do not establish a final release-head pass. Windows environment synchronization initially encountered a running DTFlow executable lock; no running application was terminated.
- PR #173's queues-only offline render completed 90 states; its five activity-width cases were separately rerun after the fixture correction. These are fixture/layout checks, not broad native Windows/DPI or packaged acceptance.
- The owner reported a working one-folder Windows build and qualitatively faster startup after resolving a disk-space failure. That is not exact-artifact acceptance of 5.3.0 or a controlled one-file/folder comparison.
- Keep #169, #170 and #178 open for their remaining startup, progress/visual and packaged acceptance work. Existing Logs memory/fault and platform limitations remain separate; see #106, #107, #88 and #77.
- No real generation, upload or model download is required for release preparation. Publication is gated on identity/checksum verification and owner smoke acceptance of the exact final Windows executable.
