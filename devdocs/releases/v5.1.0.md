# DTFlow 5.1.0

Release preparation: 2026-10-21. Not published; the final clean Windows executable requires owner acceptance before publication.

## Highlights

- **Build and run queues more easily:** a center-panel composer with inventory-backed choices, removable chips and a live item preview; Start now, Add to queue and Save paused make the next action explicit.
- **Reproducible variation:** random input draws, weighted prompt choices, wildcard lists and seeded prompt edits share one recorded Plan seed, with resolved prompts and planning evidence retained per item.
- **Keep working while generation runs:** edit the next request, put queues up next, or use the header Queue popover without leaving the tab. Relaunch a queue or retry one failed item without changing history.
- **Clearer Logs:** separate Component/Event sorting, counted Refresh, useful empty states and cancellable snapshot exports of the current session.

## Added

- **Random planning and prompts:** Pair/Cross dimensions draw distinct listed values or random seeds; plan files also support numeric ranges. Prompt variation supports `{a|b}`, multi-choice and weighted choices, inline/file wildcards, sampled or exhaustive combinations, and seeded shuffle/drop/add edits. Plans stay offline and bounded to 1000 items; wildcard hashes and resolved requests preserve what was used. Plan format 2 reads version 1; CLI `queue add` adds `--rng-seed` and `--wildcards-dir`. See the [Queues guide](../guides/queues.md).
- **LoRA sets:** vary whole lists with independent weights, including no LoRA, in Pair/Cross. Sets and LoRA-weight sweeps cannot be combined; cloud receipts remain bound to items using their LoRA. Compatibility is not inferred.
- **Quick Queue:** the header stack button and Generate dropdown share a popover for Repeat N times or a valid Composer plan. Add to queue remembers intent during a single generation and starts afterward while this window remains open; deferred work checks shutdown state.
- **Relaunch and Retry item:** create a new queue from recorded items using same or new seeds, optionally only failed/cancelled/no-result items. Original attempts stay unchanged. Staged Inpaint inputs and recorded consent are reused only when inputs remain available. CLI `queue relaunch` supports `--new-seeds`, `--failed`, `--item` and `--jobs`, saving paused.
- **Queue timing:** elapsed time and a labelled ETA use successful durations, observed concurrency and running-item ages. Timing snapshots retain elapsed, ETA and projected total. Estimates count down and rebase; mixed workloads remain rough estimates, and progress bars show actual settled counts.

## Changed

- **Queue workspace:** contextual actions, grouped Running/Up next/Paused/History rows, outcome filters, queue-specific Max at once and history removal that preserves attempts and outputs. Only the queue list scrolls in the left rail; Filter and Clear history remain accessible.
- **Composer:** inventory-backed models/samplers, size presets, numeric adders and typed prompts/seeds/weights feed a background, coalesced preview. The right inspector shows the new queue; controls and actions wrap at narrow widths, long identifiers/LoRA lists fit their card, and invalid/empty plans collapse the preview without silently resetting requested draw counts.
- **Up next:** edit Generate and Inpaint while an immutable captured request runs. Queue handoff claims the next queue atomically; Earlier/Later reorder waiting work. Auto-play stops on failure, local stop or close, and waiting queues return to paused on owner restart. CLI `queue start` still runs only the named queue.
- **No-result outcomes:** unknown items no longer block queues or backend reservations, but are never automatically replayed. Local Draw Things may still finish an abandoned job before subsequent work. The acknowledgement override is removed; hidden compatibility `queue override` is a no-op, and `queue start` exits 3 for unknown items.
- **Cloud concurrency:** Max at once allows 1–10, retaining default 4. Text-to-image admission reserves 32 MiB per generation within a shared 320 MiB budget. This is client admission policy, not measured native peak memory or guaranteed provider concurrency/entitlement; edit reservations remain conservative.
- **Logs navigation:** independent Component/Event sort targets, matching-arrival counts and incomplete-state disclosure on Refresh, an empty-state panel, non-consuming outside-click detail dismissal and visible read activity.

## Fixed

- Composer mode selection works by mouse and keyboard; narrow layouts preserve action access, control values and full wrapped inspector text. Hidden Strength controls leave no empty slots. Selecting a new queue clears prior outcome filters; interrupted queues offer Resume without replaying uncertain attempts.
- A random generation seed is retained across preview and creation, so the created queue matches its dry run. Returning to the page invalidates the summary for backend/Inpaint source changes. Wildcard nesting checks are order-independent, impossible draws show an inline error, and prompt edits try more samples before refusal.
- Logs exports pin the source session at start, follow rotation renames and exclude later appends. Progress/cancel and final results survive leaving Logs; incomplete evidence is disclosed. A conservative selection-byte admission refusal prevents partial success, but does not establish full pipeline memory-budget compliance.

## Upgrade and compatibility

- Close other DTFlow instances and back up durable state and outputs before upgrading. Do not run concurrent Windows/WSL SQLite writers.
- **Execution DB schema 4:** opening schema 1–3 first creates `attempts.pre-v4-from-v<old>-<uuid>.sqlite3` beside the database, then migrates to support up-next state/order. Older builds reject schema 4. A database backup is not an output backup; do not overwrite current state or replay ambiguous attempts when considering downgrade. See [runtime layout](../architecture/runtime-layout.md).
- **Plan files:** version 2 reads version 1; older readers reject version 2. Saved cloud concurrency above 4 is also incompatible with older builds. Older outcome handling is not equivalent to the new non-blocking no-result policy.
- Generic CLI/config generation remains txt2img-only; staged Inpaint queues retain existing permit/input/compatibility boundaries. No broader backend/model support is implied.

## Known limitations

- Native Windows interaction/DPI and the exact final clean EXE require owner acceptance. Offline screenshots are layout evidence, not packaged or live acceptance.
- Logs end-to-end memory/startup budgets remain [#106](https://github.com/djebaz/dtflow/issues/106); native/fault/export/policy acceptance remains [#107](https://github.com/djebaz/dtflow/issues/107). Existing [gallery/preview](https://github.com/djebaz/dtflow/issues/88) and [WSL2 original-access](https://github.com/djebaz/dtflow/issues/77) limits remain.
- Random prompt sampling is bounded, not proof that no further distinct prompt exists. Preview invalidation uses observed wildcard-file fingerprints, not continuous filesystem monitoring.
- Remote cancellation is not guaranteed. Repeating a remote-successful request after local save failure can consume credits; retry controls do not make automatic replay safe.
