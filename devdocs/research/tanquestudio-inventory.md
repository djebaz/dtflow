## Findings that should shape DTFlow plans

1. **Absence from inventory is not failure (TS-03).** DTFlow's preflight and the `lora-assets` plan should treat a model missing from Echo inventory as "cannot confirm", warn, and not block, at least for the Bridge/DT+ paths. Upstream's evidence is a source comment recording a 2026-09-07 measurement, not DTFlow evidence; confirm with a separately authorized check before relying on it for cloud.
2. **Stopping the wait does not stop the server (TS-02).** Upstream's own spec says client-side cancellation leaves Draw Things rendering. This agrees with DTFlow's uncertain-outcome policy.
3. **Request-derived deadlines (TS-02).** A fixed short timeout kills healthy renders; a fixed long one hides hangs. The backend contract's timeout policy should keep deadlines derivable from request size and allow overrides. The upstream formula is a data point, not a DTFlow default.
4. **Dimensions and the config that describes the image (TS-07).** Wire dimensions are floored to the 64-pixel grid upstream; metadata must record the effective size. This reinforces the requested-versus-wire mapping tests in 2B.
5. **Batch seeds are derived (TS-08).** If DTFlow supports batch counts above one, reproducibility metadata must record derivation, not only the base seed.
6. **Shared secret on Echo (TS-01).** The local gRPC adapter should support a protected server; confirm this is covered in the 2B fixture scenarios.
7. **Spec drift is real upstream (TS-20/21).** Their own spec documents corrections to earlier sections. DTFlow should pin workflow semantics before Phase 10 rather than port from prose.

## Exclusions and gaps

- **Not inspected line by line:** the inventory covers feature families. Source files such as the StoryFlow engine (about 1,600 lines) and the generate view model (about 1,300 lines) were located and sampled, not audited.
- **Not run:** no TanqueStudio test, build or behavior was executed. Test names were read as evidence of intended behavior only.
- **Excluded from near-term parity with reasons:** TS-22 (no portable backend path), TS-16, TS-17, TS-23, TS-24 (not required for generation; backlog), TS-25 (UI presentation).
- **Unresolved:** upstream license (TS inventory header), whether any TanqueStudio logic may be reused (design reference only until clarified), and any feature added after the pinned commit.
