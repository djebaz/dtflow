# WSL 1 / Pentium E6500 source smoke (2026-10-16)

## Scope and environment

Ubuntu 24.04 under WSL 1 (`4.4.0-19041-Microsoft`), Intel Pentium E6500,
Python 3.13.16, uv 0.13.1, DTFlow 4.0.0 source checkout. This is bounded
development evidence, not general Linux, packaged or provider acceptance.

## Installation and CPU findings

- uv installation failed while copying build dependencies. Owner-supplied strace
  showed `copy_file_range` returning ENOSYS, then `sendfile` with count 2147479552
  returning ENOMEM. A standalone 4 KiB file reproduced failure for that count;
  count 4096 succeeded. Concurrency one and copy/hardlink attempts did not resolve it.
- pip built and installed the editable application. For the workaround, export
  runtime requirements from `uv.lock`, then install that complete list with pip
  `--no-deps`, followed by the editable project with `--no-deps`. Ordinary pip
  resolution rejects the intentional NumPy 2.3.5 override against drawthings-py's
  declared requirement. The uv lock remains canonical; no dependency pins changed.
- Owner GDB evidence located SIGILL at `pinsrq` in Shiboken 6.11.2. The CPU lacks
  SSE4.1. A separate agent-created environment successfully imported Shiboken,
  QtCore and QtWidgets 6.8.3; owner then installed that matching pair in the WSL
  environment. NumPy and ONNX Runtime imports passed; no model inference was tested.

## Startup guard and display

Qt 6.8.3 lacks `QFile.supportsMoveToTrash`. The compatibility fix treats a missing
or non-callable capability API as unavailable: startup continues, Images Delete
is disabled, and direct Trash source checks refuse before filesystem access.
No permanent-delete fallback, generation change or dependency downgrade ships.

VcXsrv 21.1.16.1 was first extracted without installer execution and passed a
bounded startup probe on the E6500. The owner subsequently installed it. Missing
XCB runtime libraries were installed separately. The agent verified an xcb
QApplication connection using cookie authentication and rejection without a cookie.
VcXsrv runs multiwindow with `-nowgl`; access control remains enabled. TCP binds
all interfaces, not loopback only; no firewall exceptions were created. Never
substitute `-ac` or broad firewall access for authentication.

Owner reports basic GUI smoke seems to work. Selected-toggle bold fonts differ
from Windows. Windows-created title bars followed these per-user DWM settings:
`ColorPrevalence=1`, active `AccentColor=0xff141414` (#141414), inactive
`AccentColorInactive=0x00303030` (#303030). Owner visually confirmed active and
inactive colors. These are machine-wide-for-the-user decoration preferences,
not DTFlow or VcXsrv theme configuration; they can affect other applications.

## Limitations and validation

- Secure saved credentials remain Windows Credential Manager-only. Owner reports
  cloud credentials supplied through `DRAWTHINGS_API_KEY` worked. Do not save the
  secret in shell profiles, scripts or documentation; no Linux vault support added.
- Stored Windows output paths do not resolve as Linux paths in Images. Do not
  rewrite shared database paths; separate WSL state/output fixtures are appropriate.
  Shared Windows/WSL gallery, export and Trash behavior is not accepted.
- Windows locked-environment readiness, targeted Ruff lint/format and diff checks
  passed before the owner stopped further testing. The Qt-shell run returned
  15 passed / 2 failed; all three new capability cases passed. Failures were the
  existing overlay assertion (5900 ms versus exactly 6000 ms) and the empty-saved-
  credential Check-button timeout (5 seconds). Their root causes were not proven;
  do not describe them as established baseline failures or Linux-vault failures.
- The unavailable-Trash offline preview is listed in `render_states.py`; no
  screenshots were rendered. No full-suite/build/packaged acceptance was performed.
  No training, model inference, actual Trash moves or billable action ran by the agent.
