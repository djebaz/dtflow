# LoRA conversion service (#400 / PR #409)

**As merged 2026-11-13:** DTFlow has a Qt-free, synchronous converter at `src/dtflow/services/lora_convert/`. This is a current-code reference, not the earlier [planning document](../plans/2026-11-12-lora-convert/architecture.md). The service converts a known-family `.safetensors` LoRA into Draw Things F16 SQLite/NNC `.ckpt` locally on Windows, without calling DT+ or uploading.

## Components and contracts

- `convert_lora(ConversionRequest, *, progress=None, cancel=None) -> ConversionResult` is the importable, synchronous API. Callers choose their worker thread; the converter has no Qt dependency. The request includes source/destination, required family, scale and experimental/unmatched options. The result retains output SHA-256, bytes, tensor count, exact architecture and provenance. Progress events describe reading/converting/writing/finishing, and cancellation is cooperative.
- The API refuses to replace existing outputs. `ckpt_writer.py` writes a temporary `.part` then renames it, so failed conversions do not publish a partial checkpoint.
- `registry.py` binds explicit family keys (`krea2`, `zimage`, `flux1`, `sd1`, `sdxl`) to exact architecture and status. `families/` holds their resolver/table rules; `safetensors_io.py`, `keys.py`, `numeric.py`, `ckpt_writer.py` and package-owned `data/lora_mappings.json` implement the file conversion. Historical `tools/drawthings/` remains untouched.
- `__main__.py` exposes `uv run python -m dtflow.services.lora_convert`. Single files write one destination; folders and filename globs are non-recursive and case-insensitive, and select only `.safetensors`. A batch skips existing outputs unless `-w/--overwrite` stages explicit replacement. Individual failures do not prevent other items from proceeding. Every batch writes a schema 1 JSON report.
- `-a/--analyze` enables schema 2 reports for batch **or single-file** conversions. `analysis.py` reports source dtype/rank/alpha, mapping coverage and possible shape problems. After a successful conversion, the CLI invokes existing `services.lora_family` functions to check the **output CKPT** structure and detect its family. This is not an automatic safetensors family detector, nor proof of numerical equivalence or applied LoRA effect.

## Integration and evidence

The GUI Prepare picker still accepts **already converted `.ckpt` files**. User-approved upload starts only at its explicit **Prepare N ready LoRAs** action; source conversion inside that UI is future [#401](https://github.com/djebaz/dtflow/issues/401). Source-family autodetection is #402 and metadata-editor conversion is #403. No silent provider/credential switch or upload occurs during CLI conversion. SDXL requires `--experimental`; Flux 1 and SD 1.x have an unverified-on-DT+ status in the package registry.

On 2026-11-12/13 the owner converted two real Krea 2 files on Windows, compared their 474 and 512 output tensors with Draw Things iOS reference conversions (zero missing names, shape/datatype mismatches or tensor-data hash differences), prepared them in DTFlow and confirmed their expected visual effect in DT+ generations. This is sample-specific functional smoke, not exhaustive family or packaged executable acceptance. The integrated [manual full CI](https://github.com/djebaz/dtflow/actions/runs/43327453328) ran on the pre-format stack (**695 passed, 3 skipped**). Subsequent formatting-only changes were synced without rerunning the suite. See [converter/CKPT guide](../guides/lora-ckpt-format.md) and [#405](https://github.com/djebaz/dtflow/issues/405) for remaining validation boundaries.
