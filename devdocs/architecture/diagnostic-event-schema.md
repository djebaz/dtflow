# Diagnostic events v1 — schema proposal and legacy migration inventory

**Status: proposed, not implemented.** Prepared for [draft PR #105](https://github.com/djebaz/dtflow/pull/105) from repository source at `36202c6` (2026-10-19). This is a source-based migration reference, **not an analysis of retained user log files**: none were available in this review. The [PR plan and G1–G6](../plans/2026-10-19-structured-log-viewer.md) remain the binding project decisions; this document and the [machine-readable schema](../schemas/diagnostic-record-v1.schema.json) propose the concrete v1 record shapes. Writer/reader/event integration and all acceptance are pending.

## Compact and searchable record contract

**Proposal, not shipped:** aim for reasonable storage overhead with bounded writes, responsive reads and preserved evidence. Equal byte size or a fixed percentage target is not required; any measured overhead must be assessed alongside retention and native UI impact. No representative session-byte comparison has yet been measured. This compact v1 supersedes the earlier 11-required-field envelope and 16 closed typed-event contracts.

- **Physical:** UTF-8 JSON object per LF-terminated line; no BOM, pretty-printing or partial records. Maximum 1 MiB including LF; retain the 1,000,000-byte rollover target. Do not truncate tracebacks or records.
- **Required on every record:** `v=1`, persistent increasing `seq`, source UTC millisecond `ts`, `level`, `component`, and hierarchical dotted `event`. These are stable search keys for time, severity, subsystem, event/sub-event and identity.
- **Optional:** `kind` (`event` by default; required for critical measurements and aggregates), readable `msg`, typed JSON-native `data`, source `mono_ns` for timing-critical measurements, safe correlation `ctx`, sanitized `error` and source-window statistics `agg`. `kind=aggregate` requires `agg`, and presence of `agg` requires explicit `kind=aggregate`; omitting `kind` never creates an aggregate. A record carries at least `msg` or `data`. Do not shorten useful metric names such as `elapsed_ms` or `mounted`.
- **Session identity without repetition:** `session.started` contains `data.session_id`, build/runtime identity, instrumentation and capture policy. The reader binds subsequent records to a verified file/segment identity plus that startup identity; logical identity remains `(session_id, seq)`. If the startup record or required rotated segments have been pruned, mark evidence incomplete instead of reconstructing or certifying a clean run.
- **Flexible events:** arbitrary dotted event names and safe typed `data` additions are valid without a new registration or schema modification. The catalogue documents important semantics but is not an exhaustive whitelist. Only benchmark-critical (`gallery.gui_gap`, `gallery.scroll_intent`, `gallery.query_done`) and evidence-integrity (`session.started`, `session.closed`, `diagnostics.loss`, `diagnostics.record_rejected`) events have required consumer fields; additional safe fields remain allowed even there.
- **Search:** filter on top-level `ts`, `level`, `component`, `event` (exact or prefix), and `seq`; advanced filters compare typed `data.*` paths, e.g. `data.mode = grid` or `data.elapsed_ms >= 100`. Search sanitized `msg` and permitted structured values, without extracting fields from formatted messages. Whole-retained-session filtering/sorting/counting stays in the shared Qt-free, cancellable, bounded-memory reader.
- **Privacy and safety:** permissive event extensions do **not** authorize arbitrary request objects, paths, prompts, exception locals, cloud metadata, tokens or protobuf contents. One shared bounded capture/redaction implementation must allowlist keys and values, serialize only finite JSON-native data, and account for losses. JSON Schema validates the decoded line shape, not sanitization, line byte size, rotation, timestamp truth, or full-session completeness.
- **Volume:** preserve normal vs `-x` verbosity, batching and thresholded GUI-gap records. Avoid duplicating session metadata and redundant raw/aggregate samples. Do not drop individual events needed for PR #104 benchmark attribution or hide writer losses. Measure old-versus-new total bytes and retained evidence on the same workload before claiming storage parity; revisit rotation retention only with evidence.

## Shared query semantics — Phase 2 contract

These rules are the authoritative core query contract for the Qt-free reader, benchmark/report queries and exports; the [workspace specification](../design-system/logs-workspace.md#search-filtering-and-ordering) maps controls onto it. Use bounded structured predicates, not a general-purpose expression language, executable expressions or independently interpreted UI strings. Combine supported predicates with AND before page selection under G4.

- **Presence and null:** a missing path never matches, including `!=`. A null operand supports only `=` (present null matches) and `!=` (present nonnull matches); other predicates on null do not match. `false`, `0`, empty strings and null are never silently treated as missing.
- **Types/operators:** apart from the explicit null-presence rule, equality/inequality require compatible scalar types, with integers and finite fractional numbers sharing the numeric type. Numbers compare without string coercion; booleans are not numbers. Relational operators apply only to numbers; `contains` applies only to strings. Incompatible operands never match, including `!=`; unsupported operators or malformed predicates return a query error, not a complete empty result.
- **Strings/search:** structured string `=`/`!=` are case-sensitive exact comparisons; string `contains` and free text use Unicode casefolded substring matching. Free text covers safe `msg`, `component`, full `event`, structured keys and permitted scalar values, not a formatted display row or inferred fields. Null/boolean scalar search spellings are JSON `null`/`true`/`false`; numbers use their locale-independent JSON spelling.
- **Paths/collections:** represent paths internally as a list of literal object-key segments, e.g. `["data", "elapsed_ms"]`; the UI's `data.elapsed_ms` is a label, not an escape-sensitive parser. Keys containing dots/backslashes remain literal segments selected from discovery. V1 typed predicates do not index/expand arrays or compare objects/arrays; free text may visit permitted nested values within shared traversal budgets. No wildcard path language or implicit any-element matching.
- **Event families:** an exact predicate matches the entire original event. A prefix `p` matches `p` or descendants beginning `p + "."`, never `p` as an arbitrary substring (`galleryx` is not in `gallery`). `gallery.*` is a UI label for the `gallery` prefix predicate, not a regex.
- **Time/sort:** inclusive time bounds compare parsed source UTC `ts`, not formatted strings. Time sorts by source instant; event/component sort by casefolded full value then original value; severity uses DEBUG < INFO < WARNING < ERROR < CRITICAL. Numeric-metric sorts use only finite recorded numbers, with missing/null/incompatible values last in either direction. Apply requested direction to the primary key and always use ascending `(session_id, seq)` as the final deterministic tie-break. Preserve original names/values and do not compare clocks from unproven common domains.
- **Shared projections:** the versioned semantic characteristic order in the workspace specification is shared by compact rows, inspector and human-oriented CSV columns; reader sort keys use that same documented value projection, never chip position/color, visual truncation/rounding or another consumer's guess. Theme colors are display-only. Units derive only from recorded names/explicit contracts, never magnitude; do not invent metric labels, p95, duration units or severity promotions. Raw records are not reordered to mimic the display.

## Canonical sessions versus derived JSONL excerpts

Canonical session discovery accepts only the configured log directory's verified `dtflow-<session>.jsonl` and rotation siblings under G4. A selected/matching export is a **single-source-session excerpt**, not another session: use a noncanonical default basename `diagnostic-excerpt-<export-id>.jsonl` and adjacent `<basename>.manifest.json`. Export destinations must not overwrite canonical diagnostics or create a name accepted as a canonical session in the configured log directory. Excerpts are excluded from automatic session discovery and clean benchmark scoring; adding excerpt import to the app is outside this slice.

Keep the v1 record schema unchanged: preserve original `seq`, source time and recorded content subject to the shared read/export privacy boundary. Intentional selection gaps are not source loss; never renumber records or manufacture `session.started`/`session.closed` to fill gaps. Copied startup/close records, if selected, remain source records and cannot certify the excerpt. Raw clipboard copies have no manifest and must be described as excerpts, not independently certified sessions.

The small versioned export manifest is derived provenance, not durable generation state, a second logger or a source completeness seal. It contains:

- `manifest_version=1`, `artifact_kind="diagnostic_excerpt"`, export ID/time, source `session_id` and record `v`.
- `source_evidence`: the reader's pending/complete/incomplete/incompatible status **at the pinned snapshot**, with safe reason codes. Selection gaps and an unfinished source session do not become an export failure or a newly complete source. Missing source startup/continuity remains explicitly unverified/incomplete under G4; do not invent identity from a record payload or use the manifest to upgrade evidence.
- `snapshot`: the retained canonical segment basenames and captured byte boundaries, plus observed first/last source sequence where available; no absolute source paths, OS handle details, credentials or private payloads. Metadata is bounded by G4's segment set.
- `selection`: selected/matching scope, the normalized bounded query/sort when applicable, query/projection policy versions and exported record count. Original sequence numbers remain in the JSONL; no unbounded duplicate ID list in the manifest. Filter text/values pass privacy sanitization; a redacted selection is labeled non-replayable, not claimed equivalent.
- `artifact`: exported basename, byte length, streaming SHA-256 content digest, first/last exported sequence when nonempty, and `export_status="complete"` only after the requested excerpt finished. The digest binds this manifest to its data file, not to authenticity or source completeness. The manifest's source status and artifact completion are separate facts.

Write data and manifest through worker-owned temporary files and publish the completed manifest last. The pair is not atomically committed as one filesystem object: a missing/mismatched manifest, cancellation, failure or disappearing required source segment must leave no valid completion claim; report the operation incomplete and any partial artifact explicitly. Never silently overwrite an existing pair. Metadata and streaming checksum accumulation obey G4 bounds. Privacy revalidation takes precedence over byte-faithful copying: if accepted source bytes must be re-sanitized, label the export transformed rather than claiming a raw byte copy.

## Semantic decisions before Phase 1

- **Ordinary vs typed:** consumer-critical event fields require review; ordinary new dotted events and sub-events require no schema registration, and unstructured Python messages go to `logging.message`, with no extracted machine data. Keep existing levels and -x verbosity boundaries unless the PR explicitly changes them.
- **Aggregation ownership:** `gallery.source_summary` represents summaries already computed in `_PerfBatchStats`. `gallery.performance_aggregate` represents listener aggregation over retained *source measurements* and requires a real sample-population/metrics object. Both have explicit source window bounds. Do not merge, reaggregate or compute a global p95 from summaries.
- **Named event completeness:** the schema requires only critical consumer fields; other dotted event names and safe `data` additions are inherently extensible. Add documentation when an automated consumer depends on a field, without turning the catalogue into a mandatory event registry.
- **Field types:** numeric milliseconds and bytes are numbers, counts/offsets are nonnegative integers, flags are booleans, absent optional context is omitted. Current string literals such as `error=none` map to an explicit no-error value in v1; never mistake text `"False"` for JSON `false`.
- **Event count vs sample count:** `seq` identifies persisted records, not input observations. `session.closed` counts reconcile writer losses separately from intentional aggregation; a successful close record exists only after drain and flush. Missing/unsupported/lost events invalidate clean benchmark evidence even if the data file is well-formed.
- **Timestamps:** source `ts` and (when relevant) `mono_ns` must be captured before queueing; aggregates give first/last source windows. Do not attribute scroll stalls to listener write time or derive source chronology from rotated filenames.
- **Privacy and volume:** avoid unbounded arbitrary `repr`, protobuf, backend dict, exception locals, prompt, cloud reference, image bytes or filesystem paths. Separate allowed generic log message text from safe typed payload; subject both to existing and enhanced redaction.
- **Schema versioning:** increment record `v` for breaking envelope/type/required-field changes; additional safe ordinary event families do not require a new schema or catalogue entry. Readers reject unsupported versions explicitly. Retained pre-JSONL text/CSV remains untouched and unsupported by new readers.

## Contract versus validation limits

[JSON Schema v1](../schemas/diagnostic-record-v1.schema.json) validates the shape of a **single decoded record** and typed data for the initial critical event IDs; it is **not** a validator for bytes-on-disk, secret safety, session completeness or PR #104 clean-trial semantics. The JSON Schema file is design documentation, not a new runtime dependency. The implementation must enforce G1–G6 and the event-specific privacy allowlists independently.

## Implementation handoff

1. Phase 1: reconcile all logging sites against this inventory, reconcile benchmark-critical mappings and inventory representative logging families without registering every ordinary event, and keep typed key definitions in one module/schema authority; preserve current measurement cadence before replacing string producers.
2. Phase 2: use the shared validator/reader for all viewers, exports and #104 benchmark tools; certify evidence completeness only after seal/rotation/loss checks. Do not use a second set of regex field maps.
3. Phase 3: render synthetic instances of the *same* schema in the native Logs table; do not invent one-off UI formats or bypass the shared redaction boundary.
4. Deferred owner/CI: reconcile affected tests, run exact-head checks and native Windows benchmark replay/large-log UX under G6 before Ready/Merge. No tests or validation were run to produce this audit.
